# 개발 도구 마이그레이션과 제품 런타임 변경 구분

개발 도구의 모델 전환 요청을 제품 내부 모델 교체로 해석하면, 기술적으로 타당한 조사와 테스트도 잘못된 목표를 강화할 수 있다. 지정한 스킬, 개발 도구, 제품 런타임 중 실제 변경 대상을 원 요청과 대조하고 상세 계획 전에 확정한다.

에이전트가 만든 잘못된 범위는 후속 진행 지시만으로 정당화되지 않는다. 사용자가 전제를 지적하면 기술 설명을 반복하지 말고 원 요청으로 돌아가 계획과 승인 기록을 정정한다.

프로젝트 근거: Evelyn `docs/worklog/2026-09-23.md`의 확정된 범위 오해 정정·재발 방지 기록. 철회한 런타임 교체안은 실행 근거로 사용하지 않는다.
