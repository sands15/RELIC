# 2026-W38 주간 개발 회고

9월 14일~20일 회의 시점까지의 기록과 협업을 검토하고, 9월 20일 아래 합의와 공개를 사용자에게 최종 확인받았다. 프로젝트 검증은 각 원본에 기록된 당시 결과이며 이번 회의에서 제품·실서비스를 다시 시험한 것은 아니다. 회의 기록은 대화 원문이 아닌 확인된 결과와 합의의 요약이다.

## 검증된 결과

- **CAD — 형상 보존과 대상 앱 호환성을 별도로 확인한 기록이 있다.** Nintendo Switch 디텐트의 최종 C3 전체 3MF는 내부 XML 검사를 통과했으나 사용자에게 전달한 뒤 Bambu Studio 불러오기 실패가 발견됐다. 패키징 교정 후 실제 앱 불러오기를 확인했다. Joy-Con 그립의 부분 수정에도 보호 영역·최종 메시 비교 기록이 있다. 이러한 부분 검증은 전체 디자인 수용, 실물 체결·강도·내구성 성공을 뜻하지 않는다. 근거: [[Daily/2026-09-14]], [[Daily/2026-09-17]], [[Daily/2026-09-18]]; Nintendo Switch detent 프로젝트 `outputs/plan.md`의 `Final C3 Bambu load repair — 2026-09-14`, Joy-Con 그립 작업 `outputs/plan.md`. CAD 원본의 공개 링크·전용 색인은 아직 없다.
- **Evelyn — 검색 결과 전달 경계의 결함과 입력 예산 한계를 분리했다.** P69는 뒤쪽 정정이 조용히 잘리는 문제를 source/offline에서 교정하고, 초과를 명시적으로 보류하도록 검증했다. P70은 검색 개수를 줄이는 것이 필요한 근거를 모두 전달하는 해결책이 아님을 통제 시험으로 확인했다. P71은 설계 검토 상태이며 이 기록의 근거 시점에는 구현 승인 대기다. 전체 장문 활용·실제 대화 품질·운영 채택의 증거가 아니다. 근거: [[Daily/2026-09-16]], [[Projects/Evelyn]], [9월 16일 원본](obsidian://open?vault=docs&file=worklog%2F2026-09-16)의 P69/P70, [9월 18일 원본](obsidian://open?vault=docs&file=worklog%2F2026-09-18)의 P71.
- **Evelyn — 로컬 STT 비교 도구의 회귀와 합성 음성 연결 검증을 수행했다.** 기본 모델의 부스팅 미지원 조건을 발견하고 해당 기능을 지원하는 모델 파일을 고정한 기록이 있다. 사용자 발화·실제 마이크 경로와 인식률 우열은 미검증으로 남긴다. 근거: [[Daily/2026-09-18]], [STT 비교 문서](obsidian://open?vault=docs&file=STT_CMD_COMPARISON), [9월 18일 원본](obsidian://open?vault=docs&file=worklog%2F2026-09-18)의 CMD STT 단어 비교 환경.
- **Codex 작업 방식 — 승인한 전역 지침 개편을 적용했다.** 원래 요구·보존 조건·미정 결정, 개발 항목과 수용 검사, 새 충돌 질문, 최종 산출물 검증을 중심으로 재편했다. 승인 문안 일치·기존 보호 규칙 보존·독립 정적 검수를 확인했다. 작은 격리 예제에서 실패 후 수정·재검사와 검사 파일 보존을 확인했고, 가상 상황 다섯 건의 응답을 살폈다. 실제 Blender 품질·효율 개선의 증거는 아니다. 근거: Codex 전역 `AGENTS.md`, 비공개 로컬 `AI_에이전트_파이프라인_개편설계.md`의 적용·검증 결과. 공개 원본 링크는 없다. 이 개편 승인은 Evelyn 제품 코드나 새 실험 승인이 아니다.

## 프로젝트 간 배움

- 새 충돌을 발견한 것은 기존 디자인이나 보존 조건을 임의로 바꿀 허가가 아니다. 미정 선택과 구현 세부사항을 구분해야 한다.
- 내부 검사 통과와 최종 사용자 경로의 수용은 다르다. 실제 주장에 필요한 경계만 검증하되, 필수 앱 검사를 소스 검사로 대체하지 않는다.
- 스킬 설치·활성, 에이전트의 탐색, 실제 사용은 서로 다른 사실이다. 하위 에이전트의 결론도 핵심 근거와 대조한다.

## 기록 품질

- 의미 있는 결과 수: 이 회고가 요약한 주요 결과 4묶음. 전체 작업량이나 독립 결함 수를 뜻하지 않는다.
- Daily에 기록된 결과 수: 위 4묶음 중 프로젝트 결과 3묶음은 해당 Daily에 기록됐고, 전역 지침 개편은 로컬 설계·검증 기록과 이 회고에 남긴다. 주간 Daily 파일은 9월 14~18일의 5개다. 19~20일 파일 부재를 작업 부재로 해석하지 않는다.
- 정확한 원본 링크가 있는 결과 수: Evelyn 결과 2묶음은 정확한 문서와 절을 Obsidian 링크로 연결했다. CAD와 전역 지침 개편 2묶음은 원본 파일·절을 식별하지만 직접 열 수 있는 공개 원본 링크가 없다. Daily 링크를 프로젝트 원본 링크와 같은 것으로 세지 않는다.
- 뒤늦게 발견한 누락: CAD 전용 프로젝트 색인이 없고 Evelyn 색인의 대표 이정표는 9월 4일에 멈춰 있다. 이번 회의에서는 색인 전체 정비를 수행하지 않는다.
- 링크 품질: Obsidian 원본 링크는 해당 로컬 vault가 있어야 열리므로 공개 웹 접근성과 다르다. 회고 저장과 함께 홈의 최근 확정 회고 링크만 갱신한다.
- 기록 시간과 재탐색 절감 효과: 미측정이며 사용자 확인이 필요하다. Computer Use가 느리고 토큰 소모가 컸다는 평가는 사용자 체감으로 기록하고, 이번 주 전체의 시간·비용 절감률을 추정하지 않는다.

## 협업 회의

### Codex의 개선 약속

- **의도·보존 조건을 먼저 이해한다.** 참조 디자인을 원한다는 요청을 클립 절삭 허가로 해석한 것은 Codex의 판단 오류다. 새 간섭을 발견하면 해당 변경을 보류하고 위치·선택지·영향·권장안을 제시한 뒤 결정받는다.
- **승인 범위를 끝까지 수행한다.** 구현·수정·검수·재검증 단계마다 재승인을 요청하지 않는다. 새 디자인·정책·계약 선택은 사용자에게 묻되 안전하게 분리된 작업은 계속한다.
- **검증과 도구를 목적에 맞게 선택한다.** 반복 정밀 작업은 허용된 API·스크립트를 우선 검토하고, 화면은 필요한 시각 판단과 실제 사용 경계에 사용한다. 사용자에게 불필요한 개발 진단을 맡기지 않는다.
- **보고를 직접 확인한다.** 별도 CLI 검사 에이전트의 Superpowers 탐색 실패 보고를 설치 상태와 대조하지 않고 전달한 점을 교정한다. 후속 조회에서는 설치·활성이 확인됐으며, 그 검사에서 실제 스킬을 사용하지 않았다는 사실과 구분한다. 당시 목록을 활용하지 못한 근본 원인은 미확정이다.
- **최종 산출물 기준으로 완료를 판단한다.** 내부 검사나 중간 파일의 성공으로 사용 가능한 결과를 전달했다고 주장하지 않는다. 필요한 검사를 못 하면 미완료와 재개 조건을 명확히 알린다.

### 사용자에게 필요한 지시·결정

- 사용자가 모든 간섭과 누락을 미리 예상해 명세를 완성할 책임은 없다. Codex가 기존 맥락·참조물·실제 사용 흐름에서 중요한 빈칸을 찾는다.
- 사용자는 원하는 결과·참조물·중요한 선호를 전달하고, Codex가 구체화한 중요한 선택에 답한다. 이미 제공한 의도를 반복 설명하도록 만들지 않는다.

### 유지·중단·변경 합의

- 유지: Superpowers, 필요한 독립 검수, 원인 수정·재발 방지 검사, 검증 수준 구분. 지난주 유지 결정은 결함 방지에 대한 사용자 체감이었으며 이번 주 속도 개선이 입증된 것은 아니다.
- 중단: 미정 디자인의 임의 결정, 단계별 재승인, 불필요한 화면 조작과 사용자 진단 요구, 하위 에이전트 결론의 무확인 전달.
- 변경: 원래 요구·보존 조건·미정 결정과 최종 사용자 수용 기준을 작업의 중심에 둔다. 이 방향의 전역 지침 교체는 별도로 승인받아 적용했다.
- 보류: Seed·자동 모델 배정·별도 오케스트레이터와 새 생존 실험. 수를 채우려고 새로운 작업이나 과거 미착수 후보를 시작하지 않는다.

### 지난 공동 실험 평가

- [[Reviews/2026-W37]]의 공동 실험은 의도를 먼저 이해하고 중요한 미정 사항을 질문하여 사용자의 반복 설명·방향 교정 부담을 줄이는 것이었다. 이번 Blender 협업에서는 클립 간섭에 대한 미확정 디자인 선택을 임의 처리했고, 사용자는 지시 반영·질문·시간 측면을 부정적으로 평가했다. 이 사례에서는 지난주 약속을 달성하지 못했다.
- 전역 지침 개편과 작은 격리 검사는 개선 조치이지 실제 협업 효과의 입증이 아니다. 다음 실제 작업의 결과와 사용자 평가가 필요하다.
- A06 식량 판정 통합을 실제 생존 개선이나 Superpowers 효과의 성공 표본으로 다시 세지 않는다. 큰 생존 목표에 관한 가설과 후속 실험 선정은 보류 상태를 유지한다.

## 승격 또는 정리

- 이번 합의는 이 회고에 한 번 기록하고 Learning·Decision으로 중복 승격하지 않는다. 로컬 전역 지침 전문이나 비공개 검사 기록을 공개 Vault에 복사하지 않는다.

## 다음 주 개인 초점

- 참조 디자인과 원래 의도를 보존하고, 결과를 바꾸는 새 결정을 임의로 처리하지 않는다.

## 다음 주 공동 실험

- 다음에 사용자가 승인하는 실제 작업 하나에서 개편한 방식을 적용한다. 별도 시험용 프로젝트를 만들거나 생존·CAD 작업을 자동 시작하지 않는다.
- 성공 기준: 중요한 미정 사항을 변경 전에 질문했는가, 승인 범위의 수정·검증은 재승인 없이 마쳤는가, 최종 결과를 필요한 실제 사용 경로에서 확인했는가, 사용자의 의도 재설명·방향 교정 부담이 줄었는가를 실제 사례와 사용자 평가로 확인한다.
- 시간·토큰은 확인 가능한 계측과 비교 기준이 있을 때만 비교한다. 질문 수·검사 수·문서 수를 성과로 삼지 않는다. 이 실험 선정은 새 구현이나 외부 효과의 승인을 대신하지 않는다.
