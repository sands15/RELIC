# 2026-W39 주간 개발 회고

9월 21~27일 회의 시점까지의 협업을 검토했다. 사용자는 개선사항의 실제 적용 원칙을 승인하고 최종 결과 요약을 확인한 뒤 9월 27일 회의 종료를 요청했다. 아래는 확정한 회의 결과이며 대화 원문이 아닌 논점·합의 요약이다. 프로젝트 사실은 원본의 당시 검증 기록으로, 이번 회의에서 서비스를 재실행한 결과가 아니다. 회의 종료는 후속 개선 효과의 검증 완료를 뜻하지 않는다.

## 검증된 결과

- **Evelyn — 종료 요청 접수와 실제 종료를 구분해야 했다.** 원본에는 요청 접수 뒤 종료 보조 프로세스가 Supervisor의 Windows Job 종료에 함께 정리되어 컨테이너가 남은 원인과 후속 수정이 기록돼 있다. 수정 후 실제 종료를 확인했지만 모든 서비스의 정상 종료는 수용하지 않았다. 최초 결함을 유입한 변경과 현재 실행 상태는 이번 회의에서 확인하지 않았다. 근거: [[Projects/Evelyn]], [9월 27일 원본](obsidian://open?vault=docs&file=worklog%2F2026-09-27)의 `Control Page 명령·종료 경로 복구`.
- **Evelyn — 평가·안내의 오류를 정정한 기록이 있다.** 문장 변형을 독립 상황으로 센 Laya 자료의 품질 판정을 철회했고, 기본 실행 경로에서 지원하지 않는 명령 안내를 정정했다. 근거: [9월 23일 원본](obsidian://open?vault=docs&file=worklog%2F2026-09-23)의 `Laya D3d 문장 변형 제거 정정`, [9월 25일 원본](obsidian://open?vault=docs&file=worklog%2F2026-09-25)의 `기본 선제 대화·현재 창 관찰 요구 조사`.

## 프로젝트 간 배움

- 코드 연결 관계 탐색, 회귀 검사, 실제 사용 결과 확인은 서로 다른 역할이다. 검사 통과나 요청 접수를 사용자 결과 달성으로 확대하지 않는다.
- 도구 효과를 평가하려면 결함 발생·설치·실제 사용 시점을 구분해야 한다. 현재 설치 상태만으로 과거 작업의 사용 여부나 예방 실패를 판단하지 않는다.

## 기록 품질

- 의미 있는 결과 수: 위 프로젝트 결과 2묶음과 회의 개선사항의 실행 책임 반영 1건. 전체 작업량이나 독립 결함 수가 아니다.
- Daily에 기록된 결과 수: 위 프로젝트 결과 중 종료 경로 1묶음은 [[Daily/2026-09-27]]에 기록됐다. 나머지 평가·안내 정정은 위 원본으로 연결하며, 미확정 Daily를 공개 근거로 연결하거나 이번 회의에서 확정하지 않는다.
- 정확한 원본 링크가 있는 결과 수: 프로젝트 결과 2묶음에 원본 3개 문서와 절을 식별했다. 전역 지침은 로컬 `AGENTS.md`를 직접 대조했으며 공개 원본 링크는 없다. Obsidian 링크는 해당 vault가 필요하며 공개 웹 링크와 다르다.
- 뒤늦게 발견한 누락: 종료 결함 유입 변경과 관련 스킬 설치·적용 시점은 아직 대조하지 않았다.
- 기록 시간과 재탐색 절감 효과: 미측정. 사용자 확인 없이 추정하지 않는다.

## 협업 회의

### Codex의 개선 약속

- 이번 회의에서 확인된 판단 오류: 스킬 설치 시점을 확인하지 않고 과거 결함을 이미 설치된 스킬의 적용 문제와 연결했다. 설치·사용 이력 확인 전 효과 평가는 보류한다.
- 프로젝트 기록의 오류: 자료의 형식·개수를 실제 상황 다양성으로 확대 평가했고, 다른 실행 경로의 명령을 사용자의 기본 경로에서도 가능한 것처럼 안내했다.
- 추가로 확인한 회의 진행 오류: 이미 합의한 행동을 다시 승인받으려 했고, 실제 적용 점검보다 기록·다음 주 약속을 앞세웠다.
- 적용 행동: 변경 전에 보존할 기존 동작과 영향 범위를 파악하고, 회귀 검사는 요청 접수가 아닌 실제 요구 결과를 기준으로 선정한다. 최신 실행 환경에서 확인하지 못한 부분은 구분한다.
- 승인된 실행 원칙: 회의에서 합의한 개선은 다음 관련 승인 작업의 기존 보존 조건·수용 검사에 연결한다. 기록·적용·검증·사용자 체감 개선을 별도로 판단하고, 미적용·미검증 항목은 열어 둔다. 같은 행동의 승인을 반복 요청하지 않는다.

### 적용 추적

| 개선 행동 | 담당 | 현재 상태·근거 | 다음 확인 |
|---|---|---|---|
| 회의 합의를 실제 수행·수용 기준에 연결 | Codex | Codex 전역 `AGENTS.md`의 실행·완료 절에 반영. 이는 지침 반영이며 후속 작업 효과 입증은 아님 | 다음 관련 승인 작업의 기존 기록에서 적용·검증 근거 확인 |
| 기존 기능 보존 | Codex | 종료 실패 원인·수정 기록은 확인. 유입 변경·스킬 설치 시점·도입 후 효과는 미확정 | 다음 관련 변경에서 영향 경로와 실제 결과를 검사하고 재발 여부 확인 |
| 근거보다 넓게 판단하지 않기 | Codex | 현재 설치 상태로 과거 적용 실패를 단정한 설명을 철회하고 효과 평가 보류 | 이후 판단에서 시점·실행 경로·검증 범위를 구분했는지 확인 |
| 사용자 경험 개선 평가 | Codex / 사용자 | 미측정. Codex가 적용 증거를 수집하고 사용자는 실제 체감을 평가 | 같은 의도 재설명·고장 재발견 부담이 줄었는지 다음 회의에서 확인 |

### 사용자에게 필요한 지시·결정

- 사용자 평가: 다른 기능 개발·수정 후 기존 Control Page 명령, 특히 shutdown이 동작하지 않는 경험이 있었다. 기존 기능을 다시 발견·보고하는 부담이 핵심 문제다.
- 사용자는 관련 스킬 설치가 문제 발생 이후였을 가능성을 제시했다. 정확한 시점과 대상 스킬별 적용 여부는 미확정이며 사용자에게 기억으로 증명하도록 요구하지 않는다.
- 회의 개선사항을 실제 작업에 적용하고 확인하는 원칙과 이번 회의 결과는 확정됐다. 사용자는 원하는 결과와 중요한 선택·체감을 전달하고, Codex가 적용 증거를 수집한다. 별도 제품 구현·설치·실서비스 조작은 이 회의의 승인이 아니다.

### 유지·중단·변경 합의

- 기존 기준 유지: [[Reviews/2026-W38]]의 의도·보존 조건 우선, 중요한 미정 선택 질문, 승인 범위 내 자율 수행, 검증 수준 구분.
- 중단: 설치 전후를 구분하지 않은 스킬 평가, 접수 성공을 실제 기능 완료로 취급하는 판단, 이미 합의한 행동의 반복 승인 요청.
- 변경: 신규 기능뿐 아니라 변경에 영향받는 기존 동작의 보존 여부를 완료 근거에 포함한다. 기록만으로 개선을 완료 처리하지 않는다.
- 평가 보류: graft 및 관련 스킬 도입 후 회귀 예방 효과. 과거 결함만으로 효과나 적용 실패를 단정하지 않는다.

## 승격 또는 정리

- 합의는 이 회고에 모으고 Learning·Decision으로 중복 승격하지 않는다. 홈의 최근 확정 회의 링크를 갱신한다.

## 다음 주 개인 초점

- 사용자가 기존 기능의 고장을 다시 발견·보고해야 하는 부담을 줄인다. 실제 적용과 효과는 후속 작업에서 확인한다.

## 다음 주 공동 실험

- 적용 대상: 다음 실제 승인된 관련 변경에서 graft의 영향 범위 탐색, 관련 기존 동작의 회귀 검사, 필요한 실제 실행 확인을 연결한다. 별도 실험용 작업을 만들지 않는다.
- 평가 기준: 보호해야 할 동작과 검증 근거를 식별하고, 사용자의 재발견·재설명 부담이 줄었는지 실제 사례와 사용자 평가로 확인한다. 한 번의 무고장으로 전체 예방 효과를 입증했다고 하지 않는다.
- 상태: 실행 원칙 승인·관련 실제 작업 적용 대기. 구체적 대상 작업은 미선정이며 이 회고는 종료·재시작 등 외부 효과의 승인이 아니다.
