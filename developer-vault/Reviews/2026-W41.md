# 2026-W41 주간 개발 회고

10월 5~11일 회의 시점까지의 기록과 사용자 평가를 검토했다. 사용자가 합의 요약을 확인하고 회의 확정·기록 및 다음 실제 작업의 적용 근거 추적을 승인했다. 대화 원문이 아닌 확정 논점·행동 요약이다. 회의는 완료됐지만 다음 공동 실험은 대상 미선정·적용 NOT_RUN이다. 이번 회의에서는 제품 검사·모델·서비스를 실행하지 않았으며, 아래 프로젝트 근거는 당시 원본 기록을 확인한 것이다.

## 검증된 결과

- **Evelyn — 지난 합의 이후에도 반복 부담 감소에 실패했다.** 10월 5일 평가에서 사용자 정보 자동 갱신은 전체 목표 미달성으로 기록됐다. 저장 경로와 모델 의미 판단의 초기 분리가 부족했고, 같은 의미 오판 뒤 접근 전환이 늦었다. 진단 지시 정의 누락과 오류 응답 관측 손실도 재작업을 늘렸다. 소스 검사 통과를 전체 기능 성공으로 세지 않는다. 사용자가 보고한 이틀은 실측 작업 시간이 아니다. 근거: [[Projects/Evelyn]], [[Daily/2026-10-05]], [원본](obsidian://open?vault=docs&file=worklog%2F2026-10-03)의 `R43 전체 인과 수리와 실험 환경 복구` → `10-05 사용자 최종 평가: 대실패`.
- **Evelyn — 후속 작업에서 제한된 원인 대조와 본 실험 보류는 확인됐다.** 10월 11일 요약 정보 누락이 남자 불완전 요약에 분류를 재호출하거나 전체 40건 평가를 반복하지 않고, 같은 4건의 단일 조건 대조로 원인을 좁혔다. 이는 합의의 일부 적용 근거지만 전체 품질 수용·시간 절감·사용자 경험 개선 증명은 아니다. 후속 수리와 최초 실패의 상세 상태는 원본에 둔다. 근거: [[Daily/2026-10-11]], [원본](obsidian://open?vault=docs&file=worklog%2F2026-10-11)의 `복합 정보 요약과 Laya 분류` → `요약 충실도 보강의 알려진4 진단`, `동일4 grammar 단일변수 대조`.
- **RELIC — 공통 통신 경계 수리와 실제 로그인 확인이 기록됐다.** 인증만 임시 교정하지 않고 OAuth·계정 확인·저장소 접근의 공통 요청 경계를 수정했다. 당시 소스 검사와 같은 검토자의 관련 반례 확인 뒤 실제 로그인·새로고침 유지·로그아웃을 확인했다. 실제 첫 글 공개 쓰기는 그 checkpoint에서 NOT_RUN이었다. 현재 운영 상태를 이번 회의에서 재검증한 것은 아니다. 근거: [[Projects/RELIC]], [[Daily/2026-10-05]], [원본](../../docs/paper-reviews-plan.md)의 `실제 GitHub 로그인 및 공개 작성 연결 checkpoint`.

## 프로젝트 간 배움

- 원인을 가르는 비교는 결과에 따라 다음 행동이 달라져야 한다. 어느 결과가 나와도 같은 수정·재실행으로 돌아온다면 그 비교는 진행 근거가 부족하다.
- 올바른 입력을 넣은 처리 경로와 실제 모델 출력을 분리해 검사한다. 처리 경로 재현에는 기존 출력을 재사용할 수 있으며, 불필요하게 모델을 다시 호출하지 않는다.
- 진단 도구가 필요한 정의·실패 출력을 놓쳤다면 그 결과로 제품을 판단하지 않는다. 관측의 타당성을 먼저 회복하며 이전 손실을 복구했다고 꾸미지 않는다.
- 승인 범위 안에서 끝까지 책임지는 것과 효과 없는 접근을 계속 고수하는 것은 다르다. 중단·가설 폐기·접근 전환도 작업의 진척이며, 지침을 읽었다는 기록은 그 판단의 실행 증거가 아니다.

- 의미 있는 결과 수: 회의 평가에 필요한 프로젝트 근거 3묶음을 선택했다. 이번 주 전체 개발량·독립 결함 수가 아니다.

- 정확한 원본 링크가 있는 결과 수: 선택한 3묶음에 원본 3개 문서와 해당 절·항목을 명시했다. Obsidian 링크는 해당 vault가 필요하며 공개 웹 열람을 보장하지 않는다.
- 뒤늦게 발견한 누락: W40에서 찾지 못했던 R43 절은 이번에 지정 원본에서 확인했다. 당시 확인 실패 기록은 지우지 않는다. 개별 W40 적용 사례와 달리, 약속한 공동 실험의 단일 대상 지정부터 사용자 평가까지 닫힌 추적은 이번 검토 자료에서 확인하지 못했다. 기록 전체를 조사해 부재를 증명한 것은 아니다.
- 회수 도구 한계: workspace-brain은 오래된 색인·일부 원본 접근 불가를 반환해 실제 근거를 제공하지 못했다. 홈→프로젝트 색인→확정 W40→필요 원본 절의 좁은 직접 읽기로 대체했다. 색인 조회 성공이나 절감 효과로 세지 않는다.
- 기록 시간과 재탐색 절감 효과: 미측정. 사용자는 기다림과 반복이 여전히 더 컸다고 평가했다. 전체 실행 이력·토큰·시간을 분석하지 않았으므로 모든 반복이 불필요했다거나 특정 스킬이 원인이라고 단정하지 않는다.

## 협업 회의

### Codex의 개선 약속

- **판단 책임:** 이미 [[Reviews/2026-W40]]에 원인 수리·반복 감소 기준이 있었다. 문제를 사용자 지시 부족이나 합의 부재로 돌리지 않는다. 읽기·기록·부분 적용을 실제 부담 감소로 확대하지 않는다.
- **실패 직후:** 비용이 큰 본 실험을 멈추고 최소 실패 사례와 정상 보존 사례를 고정한다. 관련 첫 출력·설정·기준은 허용된 원래 증거 위치에 보존하며 회고·Daily에 복사하지 않는다.
- **다음 비교 전:** 기존 작업 기록에서 바꾸는 조건, 결과별로 버릴 가설, 그 결과에 따른 다음 행동을 짧게 명시한다. 어느 결과에서도 같은 수정·재실행만 이어지는 비교는 실행하지 않는다.
- **원인 분리:** 정확한 정답도 처리 경로에서 실패하면 그 경로를 수리한다. 정답은 처리되는데 모델 출력이 틀리면 모델 입력·판단을 조사한다. 같은 출력의 처리 결과 문제는 기존 출력으로 재현해 불필요한 새 호출을 피한다. 이는 원인 구별 예시이며 모델 내부 원인이 자동 확정된다는 뜻은 아니다.
- **진단 범위:** 작은 비교도 사례·호출·시간 범위를 시작 전에 정한다. 범위를 소진하면 멈춰 가설과 접근을 재평가한다. 예산 소진을 통과 사유로 쓰거나 검사 기준을 낮추지 않는다.
- **접근 전환:** 진전이 없으면 배제한 원인, 남은 불확실성, 현재 접근을 계속할 근거가 부족한 이유, 다른 접근의 최소 비교와 비용·보존 조건을 제시한다. 승인 범위의 진단 전환은 진행하고, 모델·학습·설계·권한 등 결과를 바꾸는 새 결정은 사용자에게 묻는다. 학습이 해결책이라고 미리 단정하지 않는다.
- **본 실험 재개:** 실패 사례 수리와 정상·인과적으로 연결된 경로 보존을 최종 산출물에서 확인한 뒤 재개한다. 진단 도구의 입력·관측 결함이 남으면 먼저 그 한계를 해결하거나 차단 상태를 보고한다.
- **증거 소유권:** 실제 적용·중단·전환 근거는 해당 작업의 기존 권위 기록에 Codex가 남긴다. 사용자는 선호·새 결정·체감을 제공하며, 회의를 위해 대신 진단하거나 테스트할 의무가 없다.

### 사용자에게 필요한 지시·결정

- 사용자는 기다림·반복 부담이 여전히 더 컸다고 평가했다. 유지하고 싶을 만큼 좋았던 방식은 별도로 제시하지 않았다. 기술적 일부 성과로 이 체감 평가를 상쇄하지 않는다.
- 진행 보고는 이해할 수 있었다고 답했고, 이번 주 임의 방향 결정으로 크게 바로잡아야 했던 일은 없었다고 평가했다. 보고 형식이나 중요한 선택 질문에 새 변경을 추가하지 않는다. 이를 전체 작업 만족이나 효과 입증으로 해석하지 않는다.
- 기존 기능은 수정 후 직접 테스트하지 않아 회귀 여부를 잘 모른다고 답했다. 사용자 확인 미실시로 평가 보류하며, 무고장·회귀 예방 성공으로 기록하지 않는다. 관련 자동 검증 근거 확인은 Codex 책임이다.
- 이번 실행 방식과 다음 실제 작업 적용·근거 기록, 회의 확정은 승인됐다. 다음 작업의 목표·실행 범위는 그 작업에서 확인하며, 이 회의는 새 제품 구현·모델 변경·학습·운영·설치·서비스 권한이 아니다.

### 유지·중단·변경 합의

- 유지: W40의 원래 요구·독립 기대값·기존 동작 보존·영향 범위 중심 검토, 중요한 미정 선택 질문, 승인 범위 내 자율 수행. 사용자가 이번 주 유지할 좋은 점으로 새로 선정한 항목은 없다.
- 중단: 수정했다는 이유만의 재실행, 같은 실패에도 판단을 바꾸지 않는 반복, 부분 검사 통과·지침 반영으로 사용자 경험 개선을 주장하는 방식.
- 변경: 실행 여부를 새로운 판단에 도움이 되는지로 결정한다. 실패/정상 고정 사례→구별 가능한 비교→인과 수리 또는 접근 전환→관련 보존 확인→본 실험 재개의 순서로 수행하고 근거를 남긴다.
- 보류: 실사용 회귀 여부, 객관적 대기시간 감소, 특정 스킬의 원인·효과. A06을 생존 개선 또는 Superpowers 성공 표본으로 세지 않는 기존 경계와 생존 실험 선정 보류도 유지한다.

## 승격 또는 정리

- 이 확정 회고 한 곳에 합의를 모으고 홈·관련 프로젝트 색인에 회수 링크를 추가한다. W40의 기존 근거와 원칙은 보존한다.
- 새 전역 지침·스킬·훅·감시·진단 프레임워크·별도 작업 체크리스트를 만들지 않는다. Learning·Decision으로 중복 승격하지 않는다.
- Evelyn 코드·프로젝트 상태 문서와 기존 미확정 Daily는 수정하지 않는다. 회의 기록을 별도 Daily로 복제하지 않는다.

- **기록 시점:** 반복 중단·새 가설 배제·접근 전환·수리 검증처럼 의미 있는 checkpoint마다 기존 작업 기록을 갱신한다. 끝날 때 몰아서 성공 서사를 만들지 않는다. 세부 파일·함수·검사·최종 산출물·결과와 남은 문제·담당·다음 조치는 프로젝트에 두고, 공개 Daily에는 원본의 정확한 절과 짧은 결과·한계만 남긴다.
- **성공 기준:** 무의미한 본 실험 반복을 하지 않고, 중단·접근 전환·재개 이유가 실제 증거와 연결돼야 한다. 원인 미확정이나 범위 소진을 통과로 바꾸지 않으며 기존 기능이 깨졌으면 빨라도 성공이 아니다. 필요한 제품 검증과 사용자 체감이 남으면 효과 확인을 미완료로 둔다.
- **다음 회의:** 지정된 실제 작업 원본을 이 합의와 대조한다. 적용 근거가 없으면 미적용 또는 근거 부족으로 남기고, 현재 기록의 존재를 다음 작업 효과로 세지 않는다.
