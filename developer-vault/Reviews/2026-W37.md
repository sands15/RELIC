# 2026-W37 주간 개발 회고

9월 7일~13일의 회의 시점까지 작성된 Daily와 프로젝트 원본을 검토하고, 9월 13일 협업 합의와 공개를 사용자에게 최종 확인받았다. 아래 검증 수치는 당시 기록된 실행 결과이며 이번 회의에서 제품 테스트나 실서비스를 다시 실행한 결과가 아니다.

A07 보류, A08 전체 실사용과 A12 image 등은 남아 있으며 운영 전체 완료가 아니다. 근거: [[Daily/2026-09-07]], [9월 7일 원본](obsidian://open?vault=docs&file=worklog%2F2026-09-07)의 감사 순차 구현 최종 대조, Evelyn `plan.md#audit-implementation-20260907`.
- **Evelyn — 일반 음성 대화와 개발 진단을 분리했다.** 일반 마이크 시작에 11단계 진단을 요구하던 결합을 제거하고 동의·중지 경계를 유지했다. 회귀와 배포, 실제 UI의 동의창·취소를 확인한 기록이 있다. 새 일반 경로의 발화·청취·끼어들기 전체 수용은 별도다. ASR 엔진 전환의 API/stream 검증도 실제 음성 정확도 동등성을 뜻하지 않는다. 근거: [[Daily/2026-09-10]], [[Daily/2026-09-11]], [9월 11일 원본](obsidian://open?vault=docs&file=worklog%2F2026-09-11)의 일반 음성 대화와 개발 진단 분리 및 Qwen ASR 운영 전환.

## 프로젝트 간 배움

- 부분 함수의 정확성은 사용자가 원하는 행동의 완주를 보장하지 않는다. 실제 사용 흐름의 선행조건과 끊기는 지점을 먼저 확인한다.
- 개발 검증은 일반 사용의 필수 단계가 되지 않게 한다. 사용자 참여는 실제 청취나 취향 판단처럼 대신 확인할 수 없는 부분에 집중한다.
- 실행 성공·안전 검사·속도 개선·결과 품질은 각각 근거가 필요하다. 품질 하한에 실패한 후보를 속도만으로 채택하지 않는다.

## 기록 품질

- 의미 있는 결과 수: 이 회고가 원본 근거로 묶은 결과 5개. 첫 묶음의 A06는 아래 실험 평가에서 다시 논의하되 별도 성과로 중복 집계하지 않는다.
- Daily에 기록된 결과 수: 위 5개 모두 기록됐다. 주간 Daily 7개가 있으며 Sephiria와 CAD 결과도 남아 있으나 이 회고의 5개 결과 집계에는 포함하지 않았다.
- 정확한 원본 링크가 있는 결과 수: 5/5에 프로젝트 원본 링크와 해당 날짜·절을 표시했다. Evelyn 링크는 로컬 Obsidian의 `docs` vault가 필요하므로 공개 웹 접근성과는 다르다.
- 뒤늦게 발견한 누락: 9월 1일 Toss Daily 복원은 아직 이뤄지지 않았다. 이번 주 Daily 7개에는 `Projects/` 직접 wiki link가 없고, 프로젝트 색인의 이번 주 Daily 역링크는 Toss 1건뿐이다. Evelyn 대표 이정표는 9월 4일에 멈췄다.
- 링크 품질: 여러 프로젝트 결과가 있어도 주간 Daily의 프로젝트 태그는 Evelyn만 사용한다. CAD의 상대 경로에는 원본 프로젝트를 찾을 색인이 부족하고, 9월 12~13일 Daily에는 `type: daily`가 없다. 이번 회의에서 원본 기록을 임의로 고치지 않았다.
- 기록 시간과 재탐색 절감 효과: 측정하지 않았으며 사용자 확인이 필요하다. 기록량이나 검사 수를 효율의 대리 지표로 삼지 않는다.

## 협업 회의

### Codex의 개선 약속

- 요청이 지향하는 실제 사용 모습과 완료 결과를 먼저 이해한다. 자연스럽게 필요한 구현은 챙기고, 결과·취향·정책을 바꾸는 중요한 빈칸은 이유와 권장안을 붙여 질문한다.
- 승인된 범위의 실험·구현·최적화·수정·재검증을 끝까지 진행한다. 단계 전환만으로 재승인을 요구하거나 전체 목표를 중간 보고·추천으로 축소하지 않는다. 새로운 목표·계약·외부 효과에 필요한 권한은 별도로 확인한다.
- 스스로 수행할 수 있는 검증은 스스로 처리한다. 절차를 추가할 때 막으려는 구체적 실패와 필요성을 확인하고 개발용 진단을 일반 사용의 필수조건으로 만들지 않는다.
- 근거 없는 권고와 부분 성과의 과대평가를 교정한다. 9월 12일 검색 작업에서 목표를 축소하고 검증 전 정책을 권고한 오류는 [당시 실수 기록](obsidian://open?vault=docs&file=worklog%2F2026-09-12)에 남아 있다.

### 사용자에게 필요한 지시·결정

- 모든 요구사항이나 불편 사례를 사용자가 미리 빠짐없이 정리할 필요는 없다. Codex가 기록과 사용 흐름에서 누락을 찾아 구체적인 질문을 먼저 제시한다.
- 사용자는 원하는 결과와 중요한 선택을 알려주고, Codex는 이미 정해진 맥락을 재사용한다. 사용자가 같은 의도를 반복 설명하도록 만드는 부담을 줄인다.

### 유지·중단·변경 합의

- 유지: 사용자가 체감한 결함 방지 효과를 근거로 Superpowers를 유지한다. 버그 재현·공통 원인 수정·필요한 재발 방지 검사와 증거 범위 구분을 유지한다.
- 중단: 승인된 작업의 임의 축소·단계별 재승인, 검증되지 않은 정책 권고, 일반 사용을 막는 불필요한 진단 절차, 검사 수를 근거로 한 성과 과장.
- 변경: 작업 방식의 중심을 의도 이해와 중요한 빈칸 확인에 둔다. 질문 횟수를 줄이는 것 자체를 성공 기준으로 삼지 않는다.
- 보류: 큰 생존 목표가 구체적 행동으로 이어지지 못했을 가능성은 가설이다. 원인 확정·해결책 탐색·생존 흐름 실험 선정은 나중에 논의한다.

### 지난 공동 실험 평가

- A06 안전 식량 통합은 승인된 감사 기본안 안에서 수행됐다. 서로 다른 식량 판정을 공통 함수로 교정했고 당시 선택 검사 186개 중 실패 21개를 재현한 뒤 통과시켰다. 이는 독립 결함 21개라는 뜻이 아니다. 조립본 522개 검사와 verifier 3개는 source/offline 근거다. 근거: [A06 수용 기록](obsidian://open?vault=docs&file=worklog%2F2026-09-07), Evelyn commit `3c332341`.
- 사용자가 기대한 생존·목표 행동에 대한 실사용 기여는 작았다고 평가했다. A06를 Superpowers 효과나 실제 생존 개선을 입증한 성공 표본으로 세지 않는다.
- RELIC Daily 병합·Toss 기록 복원과 Toss next-open 교정은 검토한 기록에서 별도 착수·완료를 확인하지 못했다. 완료 표본을 채우려고 자동 착수하지 않는다.
- 세 후보의 수치 판정으로 유지 결론을 만들지 않았다. 이번 유지 결정은 사용자의 전체 협업 체감 평가이며 객관적인 시간 절감 측정과 구분한다. 후보별 사전 권한 확인·승인 요청 횟수 역시 문서만으로 모두 입증하지 않았다.

## 승격 또는 정리

- 협업 합의는 이 회고에 한 번 기록한다. 같은 내용을 Learning과 Decision으로 중복 승격하거나 새로운 영구 지침을 별도로 추가하지 않는다.

## 다음 주 개인 초점

- 의도를 먼저 이해하고, 결과를 바꾸는 중요한 빈칸을 Codex가 찾아 질문한다.

## 다음 주 공동 실험

- 다음 실제 개발 작업 하나에서 원하는 사용 모습·완료 결과·중요한 미정 사항을 Codex가 먼저 짧게 짚고, 필요한 선택을 확인한 뒤 승인된 범위를 끝까지 수행한다. 이번 회의가 새 구현이나 생존 실험을 자동 승인하지는 않는다.
- 성공 기준: 사용자가 같은 의도를 반복 설명하거나 잘못 잡힌 방향을 다시 교정해야 하는 일이 줄었는지 다음 회의에서 실제 사례와 사용자 평가로 확인한다. 중복 승인과 불필요한 사용자 진단 요구도 함께 살핀다. 질문 횟수나 검사 수만으로 성공을 판정하지 않는다.
