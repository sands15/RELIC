# 2026-09-10

## 기동 검사와 실제 배포 경계 맞추기

- 비공개 서비스의 호스트 포트를 기다리는 중복 검사를 제거하고 기존 내부 health와 Compose 의존성을 재사용했다.
  서비스별 health 필드를 공통 분기에서 읽던 오류도 실제 함수의 StrictMode 회귀로 재현·수정했다.
- 관련47개 회귀·독립 검토와 실제5개 서비스 HTTP 계약을 확인했다. 이는 마이크·스피커 수용이나 음성 성능 개선 증거를 대신하지 않는다.
- 실제 첫 실행에서 입력 소유권 초기화와 OFF 확인이 서로 기다리는 교착도 재현했다. 기존 durable 관측을 검증된 비활성 상태에만 연결해 안전 경계를 보존했고, 최종 관련103개 회귀와 실제 UI/API 복구를 확인했다. 실제 발화·청취 검증은 사용자 참여 대기다.
- 상세 원본: Evelyn `docs/worklog/2026-09-10.md`와 `plan.md#voice-warmup-verification-20260909`.

## 장치 준비와 UI 안내 연결

- 화자 등록을 명시 녹음·미리 듣기·명시 저장으로 분리하고, 등록 파일 수와 실제 모델 준비를 구분했다. 준비 지연 중 마이크 자동 종료와 준비 실패의 제한 재시도를 회귀로 검증했다.
- 넓은 화면 안의 좁은 패널도 별도로 검사해야 한다. 패널 폭 기반 배치로 글자·버튼 축소를 고치고 실제 브라우저의 양 테마와 좁은 화면에서 확인했다. 실제 사용자 녹음/화자 수용은 별도 조건으로 남겼다.
- 원본: Evelyn `docs/LOCAL_VOICE_ADMISSION_CONTRACT.md`, `docs/worklog/2026-09-10.md`.
- 이후 승인된 CPU 화자 runtime과 고정 모델을 설치해 offline 실제 모델 실행을 확인했다. 기본 경량 Host 설치는 보존하고 선택 의존성 목록을 분리했다. Windows base executable 경로만으로 venv 사용 여부를 판정하지 않고 실제 site-packages 주입과 실행을 확인했다.

## 실패 단계와 화면 근거 보존

- 음성 인식 일치와 전체 응답 성공을 분리하고, 답변 요청 오류를 음성 합성 오류로 덮어쓰지 않도록 실패 단계와 안전한 코드를 보존했다. 화면용 원문은 짧은 수명의 메모리 값으로 제한하고 시도·동의 변경에서 제거한다.
- 회귀·독립 검토·운영 API와 브라우저 렌더를 각각 확인했다. 합성 화면 검사를 실제 발화·청취 성공으로 대신하지 않는 경계를 유지했다.
- 원본: Evelyn `docs/LOCAL_VOICE_ADMISSION_CONTRACT.md`, `docs/worklog/2026-09-10.md`.
