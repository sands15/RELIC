# 2026-11-17

## [[Projects/Evelyn|Evelyn]] — 느린 기동을 줄이려면 해시를 줄이기보다 읽는 길을 바꾼다

원본: `docs/worklog/2026-11-17.md#model-volume-20261117` (브랜치 `feat/model-volume`, 아직 `exp`에 합치지 않음).

어제 기동 기록에서 평소 재부팅 162.5초 중 Main 모델 해시가 87초였다. 원인은 모든 모델을 Windows bind mount로 읽는 경로(스트림당 70~120 MiB/s)였다. 해시를 바뀔 때만 하는 대신 모델을 Docker 볼륨으로 옮겨, 무결성 검사는 그대로 두고 해시와 적재를 함께 빠르게 하기로 했다. 런처가 기동 전에 바뀐 파일만 복사하고, 복사본 SHA-256이 원본과 같을 때만 명세에 적는다.

배운 점:

- 병목이 저장소 경로이면 검사를 약하게 하지 말고 경로를 바꾼다. 검사를 줄이는 쪽은 느린 적재를 그대로 남긴다.
- Docker Desktop의 bind mount를 거쳐 리눅스 컨테이너가 만든 심볼릭 링크는 Windows에서 WSL 링크(reparse tag `0xA000001D`)로 남아 Windows 프로그램이 대상을 읽지 못한다. 링크는 컨테이너 쪽에서 읽어야 한다.
- 기동 경로가 여럿이면 각 경로가 무엇을 다시 켜는지부터 본다. 서비스 하나만 켜는 길(`compose up --no-deps`)이 다른 서비스를 멈추면 아무도 다시 켜지 않는다. 독립 검토가 이것을 찾았다.

적용: [[Learnings/Evidence scope is part of the result]] — 소스 시험, 일부러 되돌린 보호, 독립 검토와 실제 기동(NOT_RUN)을 나눠 적었다.

증거 수준: 소스·오프라인 시험만이다(새 시험 49개, 런타임·닥터·hygiene 2241 통과, 기존 실패 5·오류 3은 이 변경과 무관). 실제 볼륨 복사와 기동 시간은 확인하지 않았다.
