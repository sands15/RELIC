## 사용자 채점 전의 모델 실험 기준선 보존

- 동일한 기본 프롬프트와 합성 상황을 두 로컬 모델에 동시에 제공하고, 회차 입력·출력과 파일 hash를
  별도 실험 저장소에 보존했다. 생성 완료와 사람이 평가하는 품질 합격을 분리하고 첫 채점에서 멈췄다.
- 공유 GPU·서로 다른 양자화의 생성 시간은 단독 성능 순위로 해석하지 않는다. Git 줄바꿈 변환도
  입력 hash에 영향을 주므로 회차 snapshot의 바이트를 보존하고 staging 이후 다시 검사했다.
- 상세 근거: Evelyn `docs/worklog/2026-09-07.md`의 첫 동시 기준선 기록.

- 후속으로 같은 원본에 클릭 채점 입력을 연결하고, 상황 전환 시 선택 보존과 미평가/0점 구분을 실제 UI에서 확인했다. 사용자 평가 전달과 점수 확정은 별도 단계로 남겼다.

- 사용자 채점을 원본 회차와 hash로 연결해 별도 보존하고, 동일 조건의 수정 프롬프트 회차까지 실행했다. 빈 평가와 0점을 구분하며 자동 점수 보완 없이 다음 사용자 평가에서 멈추는 흐름을 확인했다. 같은 출력의 평가가 회차에 따라 달라진 기록도 원본 그대로 남겼다. 참여 모델이 바뀐 회차는 해당 Git 기록에 평가 대상을 결합해 과거 평가의 분모와 누락 검증을 유지했다. 상세 근거: Evelyn `docs/worklog/2026-09-07.md`.

- 고정 합성 상황의 사용자 평가를 끝까지 받아 평가 시점의 프롬프트와 원문을 묶어 보존했다. 반복한 개발 세트의 결과와 새로운 상황의 검증을 구분해 기록했다. 상세 근거: Evelyn `docs/worklog/2026-09-07.md`의 사용자 평가 완료 기록.

- 새 상황을 쓰는 후속 검증에서는 답변 생성 전에 사례와 고정 후보를 Git에 기록했다. 채점도 공통 파일이 아닌 해당 회차의 사례 snapshot에 연결해 과거 평가와 새 평가가 섞이지 않게 했다. 상세 근거: Evelyn `docs/worklog/2026-09-07.md`의 새 상황 검증 기록.
