# 2026-11-07

## Evelyn Control Page — 대화 기록은 "읽기 전용" 저장소로 두면 기억 노출 규칙이 하나로 줄어든다

Control Page 대화를 오래 남기고 위로 올려 더 불러오는 기능을 설계해 사용자 승인을 받았다. 먼저 "이블린도 이 기록을 읽는가"를 물었고 사람이 읽는 용도만으로 정해지자, 회상·노출 위치 계산이 빠지고 "삭제된 기억에 기댄 답을 가린다"는 규칙 하나만 남아 설계가 단순해졌다. 저장은 전용 SQLite 하나(원래 시각·고유 ID·소유자 해시), 읽기는 ID 커서, 보존은 기간 제한 없음에 디스크 상한과 사용자 지우기다. 기존 Discord 보관소(30일, 관리자 인증)는 다른 사람의 말이 섞이는 경로의 규칙이라 재사용하지 않았다. 빌더 검토가 소스를 대조해 설계가 모르던 세 가지(되살린 행의 `source`에 기대는 코드, 행을 제거하는 경로 둘, 기억 삭제가 다른 프로세스에서 실행됨)를 찾아 범위에 넣었다. 교훈: 저장소 설계는 "누가 읽는가"를 먼저 정하면 규칙의 절반이 사라지고, 설계 문서는 코드와 대조하는 검토를 한 번 거쳐야 쓰기 경로의 예외가 드러난다. 구현·테스트·라이브는 없다. 원본은 Evelyn `docs/worklog/2026-11-07.md#control-page-transcript-design-20261107`이다.
