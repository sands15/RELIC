## [[Projects/Toss Trading Bot|Toss Trading Bot]]

### 결과

- 잠긴 장전 계획의 한 종목만 받는 독립 뉴스·LLM worker와, 거래 코드·DB·브로커 자격증명에서 분리된 Discord 승인 영수증 worker를 구현했다. 두 경로 모두 매매 판단과 주문 권한이 없으며 알림 목적지를 하나로 제한한다.
- 승인 전용 clean exact-SHA release를 Mac의 분리된 불변 경로에서 검증해 Gateway 연결 smoke까지 통과했다. 전체 회귀 `442 passed`, 승인 전용 `45 passed`이며 실제 버튼·modal interaction만 사용자 로그인 확인을 기다린다.
- 운영 정본과 런타임 안전 조건이 완전히 증명되기 전까지 live를 차단했다. 현재 영수증은 shadow 감사 기록일 뿐이고 실주문 소비자·WebSocket 실행 엔진·OCO 보호 상태기계는 아직 연결하지 않았다.

### 재사용 가능한 배움

- 설명용 AI의 비영향성을 보장하려면 prompt만 제한하지 말고 독립 import graph, 최소 context DTO, 별도 state/webhook, 위험 환경변수 거부를 함께 계약 테스트로 고정한다.
- 외부 서비스에 idempotency key가 없으면 로컬 dedupe가 있어도 성공 응답 유실 중복은 남으므로 전달 계약을 at-least-once로 기록한다.
- 자동매매 노드의 배포 준비성은 코드 테스트만이 아니라 exact source revision, DB integrity, fail-safe runtime flags, 전원·절전·재부팅 복구를 함께 증명해야 한다.
- 같은 OS 사용자 안의 프로세스 분리는 보안 경계가 아니므로, 사람의 승인 기록을 실주문 권한으로 승격하려면 별도 인증 출처와 consumer의 broker·risk 재검증이 필요하다.
