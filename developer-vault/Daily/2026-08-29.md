## [[Projects/Toss Trading Bot|Toss Trading Bot]]

### 결과

- 잠긴 장전 계획의 한 종목만 받는 독립 뉴스 worker를 구현해 Finnhub 수집, 선택형 local LLM 검증, 별도 Discord webhook을 거래 package·DB·자격증명과 분리하되 모든 알림은 같은 단일 허용 channel로 제한했다.
- context 경합·조기폐장, 거래 DB 무변경, 세션 만료, 악성 LLM fallback, Discord 재시작 재전송을 포함한 전체 회귀 `372 passed`를 확인했다. 실 API·Mac 상시 운용·실주문은 아직 검증하지 않았다.
- Mac 운영 노드의 Tailscale 네트워크와 native OpenSSH 공개키 접속을 검증했다. 동시에 정본 불일치, 절전으로 인한 연결 단절, live-capable 설정, 상태 DB 무결성 실패를 확인해 배포와 외부 호출 테스트를 계속 차단했다.
- Discord Developer Portal의 기존 앱을 `주식 거래 승인 봇`으로 정리해 공개 봇과 사용자 설치를 끄고 서버 설치만 허용했으며, 거래·뉴스 webhook은 metadata의 channel이 단일 로컬 allowlist와 일치할 때만 POST하도록 고정했다. 전체 `376 passed`를 확인했다.
- 승인 봇의 최초 Mac Keychain 항목은 잘못된 값으로 판명해 폐기 대상으로 분류했고, 별도 전용 항목은 원본 대조와 독립 Aqua LaunchAgent 재조회까지 통과했다. 모든 임시 평문·helper를 제거했으며 clean 배포와 Discord E2E 전까지 worker·실거래는 비활성이다. 상세 근거는 프로젝트 `docs/development-log.md`를 따른다.
- immutable 장전 계획의 redacted 승인 봉투와 거래 코드·DB·브로커 자격증명에서 격리된 Discord 승인 worker를 구현했다. 현재 결과는 주문 권한이 없는 one-shot 영수증뿐이며, 서버 유효 권한도 대상 channel 하나만 View/Send 가능하도록 재검증했다. 전체 회귀는 `408 passed`이고 clean exact-SHA 배포와 synthetic shadow interaction E2E는 남아 있다.

### 재사용 가능한 배움

- 설명용 AI의 비영향성을 보장하려면 prompt만 제한하지 말고 독립 import graph, 최소 context DTO, 별도 state/webhook, 위험 환경변수 거부를 함께 계약 테스트로 고정한다.
- 외부 서비스에 idempotency key가 없으면 로컬 dedupe가 있어도 성공 응답 유실 중복은 남으므로 전달 계약을 at-least-once로 기록한다.
- 자동매매 노드의 배포 준비성은 코드 테스트만이 아니라 exact source revision, DB integrity, fail-safe runtime flags, 전원·절전·재부팅 복구를 함께 증명해야 한다.
