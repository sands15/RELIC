# 2026-09-09

## 멈춤 진단의 연속 증거

- 누적 상태만으로 순간적인 멈춤 원인을 단정할 수 없어, 기본 OFF인 제한된 물리 추적을 추가하고
  순서·상한·통신 의미 보존·종료 정리를 소스 검사로 검증했다. 실행 식별자와 연속 번호로 관측 누락을
  구분하며, 실제 같은 실행의 재현 전에는 원인 확정이나 수정 완료로 기록하지 않는다.
- 상세 원본: Evelyn `docs/worklog/2026-09-09.md`의 K 동일 실행 추적 기록과
  `external/mindcraft_evelyn/README.md`. 후속 승인을 받아 게임에 필요한 서비스만 기동하고 실제 연결과
  연속 관찰에서 검색 중 정지 후 이동 집중을 포착했다. 검색 순서를 보존하면서 실행을 나누는 수정과
  취소·월드 변경 회귀를 소스 검사로 검증했다. 수정 후30분 실제 관찰에서는 수초 정지가 재현되지 않았지만, 피격 조건과 자원 획득 문제는
  별도로 남겼다. 무피격 관찰을 전체 동작 수용으로 확대하지 않는다.

## 자원 사용률과 효율의 구분

- 격리한 실제 음성 서비스에서 지연과 CPU/GPU 부하를 측정하고 재시작 첫 요청의 지연을 반복 확인했다.
  사용률은 작업당 자원 효율 점수가 아니므로 고정 입력·캐시·재생 경계와 비교 기준을 함께 기록했다.
- 상세 원본: Evelyn `docs/worklog/2026-09-09.md`의 CPU/GPU 및 서비스 지연 실측.
  측정용 서비스는 정리했으며 모델 교체나 최적화 구현으로 확대하지 않았다.
- 후속으로 전체 응답·음성 생성 90회의 작업당 비용과 함수별 CPU 비용을 측정했다.
  프로파일러 수치를 무계측 함수 실행과 대조해 계측 오버헤드를 구분했다. GPU1 후속 측정은 별도 대기다.

- 후속 피격 동반 관찰에서는 공중 정지 후 이동 집중이 다시 재현됐다. 무피격 관찰의 미재현을
  전체 해결로 확대할 수 없음을 확인했고, 사망 전 정지와 사망·리스폰 공백을 분리했다.
  해당 구간 원인은 같은 시점의 CPU 증거가 없어 미확정이다. 상세 근거는 위 Evelyn 작업 기록을 따른다.
- 별도 후속 구간에서는 같은 실행의 CPU와 물리 추적을 결합해 동기 상태 파일 저장의 event loop
  차단을 확인했다. 진단 payload도 이 경로를 사용하므로 계측 영향을 함께 기록했다. 단일 비동기
  atomic 저장과 최신 snapshot 대기로 수정하고, 실패·종료 순서 회귀 및 source/image 검사를 통과했다.
  수정 후 실제 이동 관찰은 피격 조건의 전체 해결과 분리한다. 상세 원본은 Evelyn
  `docs/worklog/2026-09-09.md`와 `external/mindcraft_evelyn/README.md`다.
- 이후 피격 구간에서는 즉시 실패하는 비동기 도주 재시도가 물리 타이머를 굶기는 별도 원인을
  같은 실행의 CPU/물리 기록과 실패 회귀로 확인했다. 공유 재시도 경계에서 이벤트 처리를 양보하는
  최소 수정은 source/image 검사를 통과했다. 후속 실제 피격 세 구간에서는 물리 진행과 착지를
  관측했으며, 원래 위협·지형의 통제된 재현 및 서버 전체 일치와는 구분한다.
- 지속 CPU 진단의 frontend 연결이 대상 프로세스 종료를 지연할 수 있음을 확인했다.
  종료 대기 알림에서 진단 연결을 즉시 해제하도록 보강하고 실제 Node child의 예외·종료 시험으로
  검증했다. 대상 오류의 최초 원인과 진단 도구가 연장한 종료 지연은 별개로 기록한다.

- 미로드 공간을 나타내는 최소 블록 객체가 좌표를 요구하는 이동 callback까지 전달되는 결함을
  실제 종료 stack과 source 실패 회귀로 좁혔다. 각 호출자 대신 공유 exclusion 경계 세 곳에서
  차단하되 빈 callback의 기존 palette probe 계약은 보존했다. source/image 검사와 재참가를
  확인했으며 같은 live 조건의 재발 검증은 진행 중이다. 상세 원본은 Evelyn
  `external/mindcraft_evelyn/README.md`와 `docs/worklog/2026-09-09.md`다.

## 정규화 전에 후보를 거르기

- 음성 청크 분리에서 후보가 될 수 없는 문자까지 반복 정규화하던 비용을 공유 함수의 조건 순서만
  바꾸어 줄였다. 캐시나 새 정규화기 없이 출력·상태 동등성과 관련 회귀를 검증했다.
- CPU 시계 해상도보다 짧은 측정의 0을 성능 개선으로 쓰지 않고 누적 실행으로 비교했다.
  합성 전처리 비용 감소와 실제 첫 음성 지연 개선은 구분한다. 상세 원본은 Evelyn
  `docs/worklog/2026-09-09.md`의 SpeechChunker 전처리 최적화 및 `tools/benchmark_speech_chunker.py`다.

## 예열 완료와 서비스 준비를 나누기

- 실제 격리 서비스에서 기존 예열 함수를 호출하고 재시작 전후를 비교해, health 응답·모델 로딩·실제 추론·
  캐시 준비·출력 형식·완료 상태의 수명을 별도로 검증했다. 초기 비용을 예열로 옮기는 것과 비용 자체를
  줄이는 것은 다르며, 재시작 후 오래된 완료 표시는 별도 점검이 필요하다.
- 상세 원본은 Evelyn `docs/worklog/2026-09-09.md`의 음성 예열 실제 호출·재시작 검증이다.
  제품 수정이나 장치 전체 검증으로 확대하지 않았고 테스트 전용 실행 상태만 정리했다.
- 후속 승인으로 예열 완료를 서버 실행 식별자에 묶고, 실제 서버 재시작 뒤 동일 클라이언트가 다시 예열하는지
  검증했다. 건강 상태·완료 증거·장치 준비를 분리하고, 같은 실행의 반복 요청에서는 증거를 재사용한다.
  오래된 상태 응답과 직접 확인한 새 서버가 충돌할 때는 실제 서버를 재확인해야 한다는 경계도 회귀로 남겼다.
  상세 원본은 Evelyn `plan.md#voice-warmup-verification-20260909`와 위 작업 기록의 실행별 음성 예열 수정이다.
  제한 실제 검증과 전용 자원 정리는 완료했으며 운영 배포·장치 전체 수용과는 구분한다.
