# 2026-11-23

## [[Projects/Evelyn|Evelyn]] — 되돌아감 버그는 받는 쪽 차이를 실제 서버 패킷으로 먼저 걸러 낸다

원본: `docs/worklog/2026-11-23.md#mindcraft-position-velocity-20261123`, `#minecraft-26-3-correction-capture-20261123` (브랜치 `exp/feeling-shadow-live`, 제품 코드 변경 없음).

Mindcraft(mineflayer) 봇의 순간이동·되돌아감을 진단했다. 정적 분석으로 서버 위치 패킷을 받는 곳을 하나로 좁히고, 같은 패킷을 mineflayer와 바닐라처럼 처리하는 자체 봇 규칙에 넣어 비교했다. 만든 패킷 4종에서는 속도 처리가 3/4 달랐다. 하지만 실제 26.3 서버에서 일부러 교정을 일으켜 받은 패킷은 "전부 절대 + 속도 0"이었고, 이것을 다시 넣으면 둘이 3/3 같았다. 그래서 원인 후보는 받는 쪽에서 보내는 쪽(물리·길찾기)으로 옮겨졌다. 이어서 공개 이슈에서 같은 조합의 측정 보고를 찾았다: 클라이언트 몸 너비 0.3(double)과 서버 0.6F/2(float)의 1.2e-8 차이로 벽에 붙은 이동이 거부된다. 이 차이를 설치본으로 오프라인 재현했다(실제 서버 확인 전).

배운 점:

- 코드 차이를 찾았다고 바로 원인으로 삼지 않는다. 그 차이가 실제로 오는 입력에서 생기는지 실제 패킷 몇 개로 먼저 확인한다. 직접 만든 시험 패킷이 실제 서버가 보내지 않는 모양일 수 있다.
- 기준이 되는 구현(여기선 이미 실제 서버에서 동작하는 자체 봇)이 있으면 차등 비교와 기록 재생이 가장 빠른 고리다.

적용: [[Learnings/Evidence scope is part of the result]] — 오프라인 비교, 실제 패킷 기록, 인과 추론을 나눠 적었다.

증거 수준: 실제 서버 패킷 기록 1회(교정 2개)와 오프라인 재생이다. Mindcraft를 실제 서버에 붙이지는 않았고, 되돌아감의 원인은 확정하지 않았다.

## [[Projects/Evelyn|Evelyn]] — 정답 창은 "무엇을 알았나"와 "언제 예측하나"를 따로 잡는다

원본: `docs/worklog/2026-11-23.md#game-judge-offline-20261123` (브랜치 `feat/game-judge`, 합치지 않음).

게임 판단 코어의 오프라인 부분(공통 규격, 기록 어댑터, 객관 정답, 작은 판단망, 기준선, 판 단위 중첩 교차검증)을 만들고 새 검토를 받아 중요한 지적 8개를 고쳤다.

배운 점:

- 정답 창의 시작은 "그 표본이 이미 담은 정보의 가장 늦은 수신 시각"으로 잡아 누수를 막고, 끝은 "표본 시각 + 예측 범위"로 잡는다. 끝까지 수신 시각에 묶으면 조용한 장면에서 창이 비어 "안전"으로 잘못 찍힌다. 창이 비면 "모름"이다.
- 끝 표시가 없는 구간(멈춤, 죽음)을 무한대로 두면 판 하나의 나머지 정답이 통째로 사라진다. 열린 구간은 그 파일의 자료가 끝나는 곳이나 상태가 돌아온 첫 표본에서 닫는다.
- 동점 점수가 많은 모델(규칙, 트리, 포화된 확률)에서는 평균 정밀도를 문턱 단위로 계산해야 입력 순서에 따라 값이 달라지지 않는다.

적용: [[Learnings/Evidence scope is part of the result]] — 합성 시험 통과와 실제 게임 자료(NOT_RUN)를 나눠 적었다.

증거 수준: 합성 자료의 단위 시험뿐이다(68개 통과, 1개 건너뜀). 실제 기록기와 게임 판은 없다.
