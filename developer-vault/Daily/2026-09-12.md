# 2026-09-12

## 검색 알고리즘과 전체 경로의 비교

- 소유자 변경에 국한했던 증분 색인 실험을 본문·태그·추가·삭제·복합 변경으로 확장해 분리 데이터에서 재측정했다. 비교 경로의 임베딩 재사용 조건을 맞추고, 누락된 소유자별 ID가 다른 행을 덮어도 정상으로 보이는 결함을 오류 주입으로 찾아 수정했다. 빠른 조회와 안전한 갱신은 별도 검증 대상이며, 합성 색인 갱신 단축을 실제 파일 동기화·전체 응답 성능으로 확대하지 않는다. 근거: Evelyn `plan.md`, `docs/worklog/2026-09-12.md`의 P7 실험·독립 검산.

- 선택 규칙을 고정한 뒤 분리 데이터에서 실제 호출을 측정하고, 이어서 반복 요청률·기억 갱신률을 조합해 캐시를 검증했다. 반복 조회를 빠르게 해도 갱신 때 전체 색인을 다시 만들면 전체 비용은 남는다. 관측을 후속 최적화의 입력으로 사용하고, 정책 품질·조회 시간·갱신 포함 시간을 구분하는 실험 루프를 적용했다. 상세 근거와 남은 범위: Evelyn `plan.md`, `docs/worklog/2026-09-12.md`의 선택·fallback 정책 후속 실험. 합성 lab 결과이며 제품 적용 완료를 뜻하지 않는다.
- 그 병목을 근거로 소유자 변경만 영향 구간에 반영하는 합성 구현을 만들고, 별도 seed에서 전체 재구축과 결과 순서·세대·캐시 동등성을 재검증했다. 성공 전에 새 세대를 공개하지 않고 실패 시 조회를 막는 복구 경계를 유지했다. 변경 유형 하나의 개선을 모든 변경·제품 동시성의 해결로 확대하지 않는다. 원본: Evelyn `docs/worklog/2026-09-12.md`의 P6 검증과 남은 범위.

- 사용자 확인으로 정정한 판단 오류: 요청받은 경우·조합 실험과 최적화를 ‘선택 근거 수집’으로 축소하고, 검증되지 않은 선택 정책을 권고한 뒤 진행을 멈췄다. 문제는 후속 실험 한 번의 누락보다 넓다. 범위별 검증표, 대조 실험, 범위 내 최적화, 분리 평가와 실패 수정까지 이어가야 하며 개별 회차 완료를 전체 목표 달성으로 바꾸면 안 된다. 기존 승인 범위의 반복 작업과 새로운 외부 효과의 승인은 구분한다. 원본: Evelyn `docs/worklog/2026-09-12.md`의 선택 정책 검증 전 권고와 조기 승인 대기 기록. 전체 최적화는 아직 미완료다.

- 합성 입력으로 native 벡터 검색을 기존 구현과 비교하고, 단순한 배열 기반 정확 검색을 대조군으로 두어 자료 표현 비용과 탐색 알고리즘 효과를 분리했다. 후보 검색의 큰 개선이 전체 검색에 그대로 적용되지는 않았고, 목표 회수율 설정도 실제 회수율을 보장하지 않았다. 성능은 전체 호출 경계와 실제 결과 누락을 함께 측정해야 한다. 원본: Evelyn `tools/benchmark_memory_quake.py`, `docs/worklog/2026-09-12.md`. 실제 사용자 기억 품질·운영 통합은 별도다.
- 후속 합성 다상황 비교에서 ID·범위·어휘·벡터 조회와 추가/삭제/저장 비용을 분리했다. 후보 경계의 동점 선택만 바뀌어도 최종 가중 점수가 달라질 수 있고, 근사 검색의 누락은 저장 손상과 별도로 전수 데이터 비교/정확 검색으로 판별해야 한다. 전체 동기화와 경로 탐색의 환경 비용도 대조군으로 확인했다. 원본: Evelyn `tools/benchmark_memory_keyed.py`, `tools/benchmark_memory_vector_scenarios.py`, `tools/benchmark_memory_recall_scenarios.py`, `docs/worklog/2026-09-12.md`. 운영 구조 선택·통합 완료를 뜻하지 않는다.

- 검색 후속 실험에서 태그 누락·오분류·과다 할당을 원본 정답과 분리해 주입하고 여러 조회 조합을 비교했다. 태그를 필수 조건으로 쓰면 정답이 누락될 수 있고, 검색 결과를 무조건 합치면 정확도와 지연이 함께 나빠질 수도 있다. 조회 구조의 속도, 후보 선별의 안전성, 전체 경로의 비용을 구분해야 한다. 원본: Evelyn `docs/worklog/2026-09-12.md`의 태그·본문·벡터 조합 실험. 합성 검증이며 운영 설계 선택은 별도다.
- 후속 검증에서 작은 고정 자료의 검색 순위를 수작업 기대값·별도 내적 계산에 대조하고, 의도적으로 뒤집은 결과를 검사기가 거부하는지도 실행했다. 기대값의 산술 오류와 대상 코드의 오류를 구분했으며, 계산 검증 통과를 데이터 대표성이나 운영 성능의 증거로 확대하지 않는다. 원본: Evelyn `docs/worklog/2026-09-12.md`의 작은 순위 기준 검증.
- 후속 교차 실험에서 서로 결합된 합성 속성과 조회 경로의 불필요한 비용을 분리하고, 같은 입력의 반환 순서를 보존한 채 재측정했다. 실행 횟수와 고유 질의 수를 구분해 별도 검사기로 정답·분위수·조건부 신뢰구간을 검산했다. 조회 단축은 사전 구축·추가 메모리의 비용 이동일 수 있고, 순위 보존은 실제 의미 품질의 증거가 아니다. 원본: Evelyn `docs/worklog/2026-09-12.md`의 교차 fixture와 동등 순위 경로 재측정. 운영 선택·통합은 별도다.

## 지연 계측의 실패·전달 경계

- 기억 검색의 변경 직후 지연을 반복 측정해 단일 관측의 역전과 지속적인 회귀를 구분했다. 이후 DB에서 불필요한 열을 가져오지 않는 후보를 구현하고 새 합성 표본으로 평가했지만, 부분 처리 비용 감소가 전체 시간의 확실한 개선으로 이어지지 않아 채택을 보류했다. 중첩 계측 시간을 더하거나 넓은 GC 계측 창으로 원인을 단정하지 않는다. 원본: Evelyn `docs/worklog/2026-09-12.md`의 P10/P11 검증. 운영 반영·전체 최적화 완료는 아니다.

- 기억 검색 합성 실험에서 후보 생성용 벡터 top-K 점수표를 최종 재정렬에도 그대로 써, 어휘 검색이 찾은 정답의 실제 유사도가 0으로 취급되는 결함을 재현했다. 이미 허용된 후보의 누락 점수만 보충하자 후보 수와 가중치를 바꾸지 않고 정답이 복구됐다. 후보를 고르는 경계와 선택된 후보의 점수를 계산하는 경계를 분리해 검증해야 한다. 원본: Evelyn `docs/worklog/2026-09-12.md`의 P9 반례 수정 검증. 실험용 수정이며 운영 적용·전체 최적화는 별도다.

- 오프라인 합성 진단에서 성공 경로에만 시간이 남고 실패에는 빠지는 계측을 확인했다. 처리기 내부 시간은 요청 대기·응답 전달을 포함한 사용자 지연과 다르며, 숫자 필드 추가도 엄격한 응답 계약에서는 호환성을 깨뜨릴 수 있다. 상세 원본: Evelyn `docs/worklog/2026-09-12.md`. 실제 성능 측정이나 구현 완료로 보지 않는다.
- 이후 승인된 계측 구현을 기존 응답 계약을 유지한 채 통합하고 오프라인 회귀·독립 검토를 마쳤다. 취소된 await 뒤에도 내부 thread는 파일을 만들 수 있으므로 작업 종료·소유권 등록·정리를 확인해야 하며, 뒤늦은 worker 오류가 원래 취소를 덮지 않는지도 검증했다. 상세 증거: Evelyn `docs/worklog/2026-09-12.md`; 실제 화면/GPU 성능·운영 배포는 별도다.

## 기억 검색 변경 경계의 검증

- FTS의 색인하지 않은 ID로 반복 삭제하면 갱신 비용이 커질 수 있었다. rowid를 매번 조회하는 대조는 이득이 없었고, 한 batch에서 전체 매핑을 만들고 변경마다 갱신하는 대조는 SQL 작업량을 줄였다. 중복 ID·검색 결과·실패 롤백을 함께 검사했으며 VM 단계 감소를 실제 검색 지연 개선으로 바꾸어 말하지 않았다. 원본: Evelyn `plan.md`, `docs/worklog/2026-09-12.md`의 P22/P23. 합성 SQL 진단이며 운영 적용은 아니다.

- 기존에 완료한 파일 순회의 경로를 캐시 제거 힌트로 재사용해 별도 파일 상태 검사 비용을 줄였다. 실제 내용 읽기와 권한·삭제 판단은 그대로 두고, 회수 비용 감소와 전체 검색 개선을 따로 검증했다. 변경 직후에는 회수 시점 때문에 재파싱이 더 생기며, 더 단순한 후보보다 항상 빠르다는 증거는 아니었다. 원본: Evelyn `plan.md`, `docs/worklog/2026-09-12.md`의 P20. 합성 검증의 학습이며 운영 채택은 아니다.

- 삭제된 캐시 슬롯을 회수해 재파싱을 줄여도, 매 요청에 추가한 파일 상태 검사가 더 비싸면 실제 검색은 느려질 수 있었다. 기존 단순 후보와 같은 검색 경로를 대조하고 회수 비용을 포함해 열세 후보를 보류했다. 다음 최적화는 이미 수행하는 순회의 정보를 재사용하는 방향이며 최신 본문·권한 검사를 생략하는 것은 아니다. 원본: Evelyn `plan.md`, `docs/worklog/2026-09-12.md`의 P19. 합성 실행의 학습이며 운영 최적성·채택 결정이 아니다.

- 순차 전수 스캔에서는 캐시 용량을 한 개 넘는 것만으로 LRU 적중이 사라질 수 있었다. 파일별 최신 버전 보관은 오래된 항목 점유를 줄이고, 고정 부분집합은 스캔 재사용을 유지하지만 삭제된 파일의 슬롯을 회수하지 못했다. 실제 파일 교체 반례까지 비교해 한 정책의 유리한 조건을 보편적 최적화로 확대하지 않았다. 원본: Evelyn `plan.md`, `docs/worklog/2026-09-12.md`의 P18. 전체 지연·운영 채택은 별도 검증 대상이다.

- 함수 프로파일에서 반복 비용을 찾은 뒤 기존 최적화와 새 순수 변환 캐시의 OFF/ON 조합을 실제 검색 경로로 비교했다. 기존 최적화의 효과와 추가 최적화의 효과를 분리하니 새 캐시의 이점은 일관되게 입증되지 않았다. 생성·정리 비용과 실패 시 정리까지 포함해 검증하고 추가 후보를 보류했다. 원본: Evelyn `plan.md`, `docs/worklog/2026-09-12.md`의 P16/P17. 합성 반복 결과이며 제품 성능 보장이 아니다.

- 최신성 반례를 실제 검색 결과에서 최종 전송 보호 함수까지 연결하되 네트워크는 기록용 sink로 대체했다. 파일 자체의 변경과 색인 버전·삭제 기록의 갱신은 서로 다른 사건이며, 여러 좌표가 동시에 바뀐 테스트만으로 각 보호 장치의 인과를 입증할 수 없다. 기존 고정 버전 회귀를 재사용한 보호 우회/복원 검사로 이를 분리했다. 원본: Evelyn `plan.md`, `docs/worklog/2026-09-12.md`의 P15. 제품 전달·성능 개선 완료의 증거는 아니다.

- 전체 파일 스캔 비용을 줄이기 전에 외부 변경 시점을 주입해 최신성 경계를 특성화했다. 파일 크기·수정 시각이 같아도 내용은 바뀔 수 있고, 요청 내부의 첫 읽기 재사용도 중간의 소유권 변경을 놓칠 수 있었다. 캐시의 동기화 세대 표시는 반환 시점의 파일 최신성과 같지 않다. 반증 실험의 성공과 안전성 수용을 분리하고 최종 소비자의 재검증을 남은 경계로 기록했다. 원본: Evelyn `plan.md`, `docs/worklog/2026-09-12.md`의 P14; 제품 적용·실제 사용자 노출의 증거는 아니다.

- 잘못된 태그가 본문의 무관한 인용 문구와 겹치면 순위 합산이 오답을 올릴 수 있었다. 기존 대체 정책을 고정해 분리 데이터에서 실제 호출 비용까지 재검증했으며, 품질 개선과 속도 개선은 별개라는 결과를 얻었다. 큰 교차 행렬의 완료나 품질 gate 통과만으로 최적 구조를 선언하지 않고, 단순한 본문 검색과의 비용 절충과 전체 파일 동기화 병목을 남은 과제로 유지했다. 원본: Evelyn `plan.md`, `docs/worklog/2026-09-12.md`의 P12/P13. 합성 실험의 학습이며 제품 채택 결정은 아니다.

- 검색 최적화의 교차 실험에서는 두 구현의 같은 결과만 확인하면 같은 오류를 놓칠 수 있다. 합성 변경 이력의 정답을 독립적으로 계산하고, 소유권 이동 전후의 직접 ID 조회를 추가해 기존 검증을 통과하던 낡은 소유권 경로를 검출했다. 무변경 사건과 실제 갱신 횟수도 구분했다. 원본: Evelyn `plan.md`, `docs/worklog/2026-09-12.md`; 운영 장애 재현이나 전체 성능 최적화 완료의 증거는 아니다.

## Vision 전처리의 실제 입력 예산

- 기존 설치된 전처리기를 합성 입력으로 실행해 외부 이미지 축소와 모델 내부 resize·patch 분할이 별개임을 확인했다. 해상도 최적화는 파일 크기만 보지 말고 실제 tensor 크기와 처리 조각 수까지 확인해야 한다. 처리량 감소를 인식 품질이나 전체 응답 개선으로 간주하지 않는다. 상세 근거: Evelyn `docs/worklog/2026-09-12.md`; 실제 사용자 화면·GPU 품질 비교는 미완료다.

## 게임 업데이트의 수식 검증

- Sephiria Optimizer 신규 아이템 지원 배포본을 오프라인 검증했다. 능력치 증폭·전환·동률 처리처럼 연산 순서가 중요한 모델은 실제 게임 클래스의 격리 입력 결과와 대조하면 합성 테스트만으로 놓치는 경계를 확인할 수 있다. 조건부 발동 효과와 상시 DPS는 구분한다. 원본: Sephiria Optimizer `plan.md`, `tests/Test-UpdatedCapture.ps1`. 실제 플레이 검증은 다음 설치 단계에 남아 있다.
- 후속 점수·유일 효과 소유권 오류를 실패 재현 후 수정하고 v0.4.5 배포본을 오프라인 검증했다. 집계 필드는 점수 계산 전에 채우고, 기존 소유자의 무효화는 대체 소유자를 선택하기 전에 완료해야 순회 순서에 따른 누락을 막을 수 있다. 원본: Sephiria Optimizer `plan.md`, `tests/UpdatedItemsTest.cs`. 게임 설치·실제 플레이 확인은 별도다.
- 이후 사용자 요청으로 v0.4.5를 설치하고 이전 파일 백업, 설치본 버전·해시 일치와 자체 검사 통과를 확인했다. 실제 게임 내 로드는 다음 실행 때 확인한다. 원본: Sephiria Optimizer `plan.md`의 Installation 기록.
- 헌신 아이템의 추천 결과는 유효하지만 중간 이동이 연결 보존 조건을 깨뜨리는 실행 계약 불일치를 재현하고 v0.4.6에서 수정했다. 이미 연결된 묶음을 같은 행 안에서 최적화하도록 공통 배치 조건을 맞춰 16개 합성 조건·반복 32회 적용 순서 검사를 통과했다. 최종 상태의 유효성과 실행 가능한 이동 순서는 별개다. 원본: Sephiria Optimizer `plan.md`, `tests/Simulate-DevotionApply.ps1`. 행 간 묶음 이동·실제 게임 적용은 이번 검증 범위가 아니다.
- 후속 교차 시뮬레이션에서 하얀 종이의 최종 시너지를 보존해도 중간 교환을 통과하지 못하는 추가 추천을 재현했다. 고정 추천 재검사와 작은 상태 공간의 완전 탐색을 함께 사용해 시간 제한 실패와 실제 도달 불가능을 구분했다. 비활성 효과도 별도 카테고리 계약에 참여할 수 있어 활성 여부만으로 제약을 제거하면 안 된다. 원본: Sephiria Optimizer `plan.md`의 Cross-effect audit, `tests/Simulate-ApplyContracts.ps1`. 진단 결과이며 추가 수정·실제 게임 검증은 별도다.
- 승인 후 추천과 실행이 같은 적용 순서 검사를 공유하도록 v0.4.7을 보강했다. 하얀 종이를 고정하지 않고 기존 시너지를 유지하는 이동과 실행 가능한 대안을 선택하며, 514개 합성 추천에서 적용 순서 거절이 없음을 확인했다. 실행 가능성 검증에도 비용 한도가 있으므로 결과는 검증된 탐색 결과이지 전역 최적해 보장이 아니다. 원본: Sephiria Optimizer `plan.md`의 Final reachable-recommendation evidence, `ApplyPlanner.cs`. 배포본 검증까지 완료했으며 설치·실제 게임 적용은 별도다.

## 출력용 회전 기구의 지지면 검증

- 작은 양방향 클릭 기구를 CAD로 제작하며, 명목상 유격만 배치하는 것과 그 높이를 실제 받침면으로 유지하는 것이 다름을 확인했다. 닫힌 메시 검사와 자기교차 검사는 별도로 수행하고, 원본 결합부 보존을 형상 차집합으로 확인했다. 원본: Switch detent prototype `outputs/plan.md`, `outputs/verification.json`, `outputs/preservation_boolean.json`. 출력 적합성·클릭 토크·반복 내구성은 물리 시험에 남아 있다.
- 후속 시험 링에서 실제 기어의 축 지지가 빠져 있음을 확인하고 가이드를 추가했다. 시험편은 접촉 톱니뿐 아니라 움직임을 제한하는 지지 조건도 보존해야 한다. 수정 링의 형상·기존 축 결합을 오프라인 검증했으며, 중심이 맞는 계산의 눌림량을 유격이 있는 조립체의 최대값으로 확대하지 않았다. 원본: Switch detent prototype `outputs/plan.md`, `outputs/ring_v2/verification.json`. 소리·실제 토크·내구성은 출력 시험 전이다.
- 비교용 후속 링은 축 지지 길이를 보존하면서 주변을 출력 방향에 맞는 경사로 덜어내 CAD 부피를 약29% 줄였다. 이후 톱니 깊이를 늘리면서 중심 정렬과 편심의 공간 여유를 구분하고, 더 깊은 버전에는 탄성팔 위치를 조정한 전용 링을 짝지었다. 결합 치수 보존과 변형 전 통과 공간을 확인해도 실제 클릭 소리·토크·변형 후 간섭 여유가 입증되지는 않는다. 원본: Switch detent prototype `outputs/plan.md`, `outputs/ring_v3/verification.json`, `outputs/ring_v4/verification.json`, `outputs/ring_v5/verification.json`. 물리 성능 개선은 아직 검증하지 않았다.
- 회전방향별 접촉면을 세 단계로 비교할 수 있게 만들고, 실제 출력물 구분용 홈과 기존 부품 재사용 경계를 검증했다. 몸체가 거울 대칭이어도 같은 회전방향에 작용하는 접촉면은 회전 대응으로 배치해야 했다. 접하는 곡면을 겹쳐 만들 때의 메시 오류는 전체 윤곽을 하나로 구성해 수정하고 재검증했다. 원본: Switch detent prototype `outputs/plan.md`, `outputs/ring_v6_compare/verification.json`. 방향별 손맛과 소리는 물리 비교 전이다.
- 시험 링의 내부 톱니를 실제 구동 기어에 옮기고 외부 체인 톱니와 상부 결합부 보존을 검증했다. 두 탄성 링 후보의 고정 인터페이스가 같아 전체 밑판을 공통으로 재사용했다. 톱니 단면이 같아도 축 지지 길이와 내부 천장 여유가 달라지므로 시험편의 손맛을 완성 조립체에 그대로 일반화할 수 없다. 원본: Switch detent prototype `outputs/plan.md`, `outputs/stand_base/verification.json`. 실제 완성 조립과 소리·토크는 물리 검증 전이다.
