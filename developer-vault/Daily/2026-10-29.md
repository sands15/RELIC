# 2026-10-29

## Evelyn Mind 재설계 브레인스토밍·0~1단계

"항상 생각·들으며 준비·기능 마비를 Main이 바로 인지" 요구를 기존 구조 수정이 아닌 처음부터의 재설계로 다뤘다. 마음(판단 프로세스) 하나·몸(I/O 어댑터) 여럿·이벤트 중심의 draft 제안을 썼고 1·2절은 승인, 몸/자원/테스트 절은 검토 대기다. 기존 코드를 건드리지 않는 새 패키지에 이벤트 버스·revision·content-free 저널·6개 능력 장부·행동 관문·결정적 재생 검사를 구현해 53검사 PASS(source/offline, 런타임 미연결, 미커밋). 같은 날의 확장 동결 결정과 겹쳐 사용자에게 확인했고, 사용자는 0~1단계만 동결의 예외로 두는 결정을 승인했다. 2단계 이후는 음성 루프 실사용 PASS 또는 명시 재지정 뒤에만 연다. 출처: Evelyn `docs/worklog/2026-10-29.md#evelyn-mind-stage01-20261029`, `docs/superpowers/specs/2026-10-29-evelyn-mind-architecture-design.md`.

재사용 가능한 교훈: 연속 실패를 "시간 창 안의 trailing 개수"로만 판정하면 창이 지나는 것만으로 성공 없이 정상으로 복귀한다. 임계 초과는 latch로 고정하고 성공만 해제하며, 시간은 probe 허용만 열어야 fail-closed가 유지된다.

사용자가 개편 완료까지 제품을 쓰지 않겠다고 밝혀 전 단계 진행과 옛 경로 토글 없음을 결정으로 기록했다. writing-plans 형식의 1~2단계 계획을 먼저 쓴 뒤 그대로 실행해 Control Page 읽기 전용 능력 줄과 마음 쪽(대화·기관·transport·몸 허브·숙고기·조립·WebSocket 몸 서버)을 8개 커밋으로 남겼고 `tests/mind` 101검사 PASS(source/offline, 가짜 몸·모델 끝-끝 재생 PASS)다. 3·4단계 초안(상황 모델·예측기)에도 17검사를 붙여 PASS. 실제 장치·live는 NOT_RUN. 출처: Evelyn `docs/worklog/2026-10-29.md#evelyn-mind-stage01-20261029`, `docs/superpowers/plans/2026-10-29-evelyn-mind-stage1-2.md`.

재사용 가능한 교훈: 브레인스토밍 뒤 바로 코드를 쓰면 안 되고 구현 계획(테스트 먼저·완전한 코드·실행 명령)을 거쳐야 한다. 실제로 계획 단계에서 숙고기의 문장 절단·몸 서버 종료 뒤 상태 같은 기대값 오류를 미리 잡았다.

## Evelyn Mind 3·4단계 연결(상황 요약·예측기)

테스트만 있던 상황 모델과 예측기를 Sub/Router llama-server, `/v1/stt/streams`, 기억 저장소 공개 읽기 API에 연결했다. 부분 STT마다 가설을 만들되 발화당 Router 1회·회상 1회로 제한하고, 2초 `tick()`이 Sub 요약을 변화·간격·유휴 조건일 때만 돌린다. 끝-끝 가짜 모델 검사에서 부분 STT → 가설 → 확정 → Main 프롬프트의 `recalled:` 포함과 턴 시작 전 상황 한 줄을 확인했다. OCR·부분 발화 원문이 JSONL 저널에 없음도 파일 전체 검색으로 고정했다. `tests/mind` 163검사 PASS(source/offline); 실제 Sub/Router/STT 스트림/기억 저장소 호출과 화면·OCR을 보내는 몸은 NOT_RUN/미연결. 출처: Evelyn `docs/worklog/2026-10-29.md#evelyn-mind-stage01-20261029`, `docs/superpowers/plans/2026-10-29-evelyn-mind-stage3-4.md`.

재사용 가능한 교훈: 가설은 텍스트 접두어가 아니라 발화 단위로 묶어야 한다. 앞부분이 같다는 이유로 이전 턴의 분류·회상을 재사용하면 새 발화가 낡은 문맥을 물려받는다. 또 가짜 모델이 늘 같은 출력을 내면 "바뀌었을 때만 동작" 규칙의 시험이 가려지므로, 호출마다 다른 출력을 내게 해야 한다.

## Evelyn Mind cutover(옛 턴 경로 제거)

옛 턴 처리 경로 두 벌(Discord `VoiceTurnOrchestrator` 계열, 로컬 `_chat_stream_handler` 계열)을 토글 없이 지우고 Control Page 대화를 body-web → 마음 WebSocket 프록시로 바꿨다. 인벤토리 표를 계획 첫 Task로 두고 실행해 모듈 62개를 삭제했으며, 제거 전 커밋 별도 checkout과 모듈별 비교에서 통과하던 테스트 중 새로 실패한 것은 0이다(source/offline). 3·4단계 브랜치를 병합해 `tests/mind` 177 PASS. 마음 서비스 기동·실제 대화·live는 NOT_RUN. 출처: Evelyn `docs/worklog/2026-10-29.md#evelyn-mind-cutover-20261029`, `docs/superpowers/plans/2026-10-29-evelyn-mind-cutover.md`.

재사용 가능한 교훈: 큰 모듈에서 경로를 지울 때는 "제거 전에는 도달 가능했고 제거 뒤 도달 불가가 된 정의"만 AST로 골라 지우면 기존 죽은 코드를 건드리지 않고 고립된 보조 함수까지 정확히 걷어낸다. 단, 도달성 기준선은 수동 편집 전 원본으로 잡아야 한다(먼저 라우트를 떼면 그 뒤 보조 함수가 "원래 죽은 코드"로 보인다). 또 테스트 비교는 진행 중인 작업 트리가 아니라 별도 checkout에서 돌리고, subtest 결과는 verbose 출력 파싱이 아니라 결과 클래스로 기록해야 기준선이 믿을 만하다.

## Evelyn Mind 세 브랜치 통합

2b(Bridge를 몸 클라이언트로 교체)와 3·4단계, cutover를 한 통합 브랜치로 병합했다. 충돌 10건은 모두 문서와 테스트였고 로직 충돌은 0건이었다. 모듈별 전체 회귀에서 기준선 대비 실패가 720에서 647로 줄었고, 병합이 만든 틈 2건(게이트웨이 구성원 수 고정 단언, 삭제된 테스트 fixture 의존)을 고쳤다. 다른 작업의 미커밋 변경이 겹쳐 현재 브랜치에는 아직 넣지 않았다. 독립 리뷰와 실제 기동은 NOT_RUN. 출처: Evelyn `docs/worklog/2026-10-29.md#evelyn-mind-merge-20261029`.

재사용 가능한 교훈: 병렬로 만든 브랜치를 합친 뒤에는 각 브랜치의 단독 검사가 통과해도 전체 회귀를 돌려야 한다. 한쪽이 지운 테스트 파일을 다른 모듈이 fixture로 import하던 숨은 의존이 로드 오류로, 개수를 고정한 단언이 의도된 구성 추가와의 어긋남으로 드러났다. 병렬 실행에서만 실패하는 항목은 단독 재실행으로 가려야 진짜 회귀와 섞이지 않는다. 또 미커밋 작업이 겹치는 체크아웃에는 병합하지 말고 별도 워크트리의 통합 브랜치에서 하고 옮기는 것은 나중에 한다.
