# 2026-08-31

## [[Projects/Toss Trading Bot|Toss Trading Bot]]

### 결과

- Mac exact-SHA shadow release에서 한 달 USD 10,000 paper simulation을 시작하고, 거래 DB 권한이 없는 기존 Discord approval worker에 서버 전용 `/현황` 조회를 배포했다. Mac non-live gate와 Discord command registry read-back을 통과했으며 실주문은 계속 차단했다.
- 사용자가 `/현황` 실제 호출 성공을 확인했다. 자동선정 후보가 없는 날은 마감 직전까지 재시도한 뒤 관망 coverage로 남기되, 캔들·호가 결측은 coverage로 가장하지 않는 로직과 status schema v2를 같은 Mac shadow release에 배포했다. 설치 상태는 planner·stream·approval 3/5이며 news·watchdog은 아직 없다.
- 장전 planner 오류는 OAuth의 gzip 압축 401 본문을 잘못 decode해 원래 `invalid_client`를 가린 문제였다. gzip strict decode, loop token 재사용, terminal auth 재시도 차단을 검증한 release를 별도 준비했으며, plan·paper plan 0건을 확인하고 자격증명 복구 전까지 planner를 정지했다. 현재 run을 중간 분할하지 않고 다음 실험부터 서로 다른 두 종목·가상현금 50:50의 고정 2레인을 쓰기로 했다.

### 재사용 가능한 배움

- 운영 조회 명령은 거래 DB를 직접 열게 하지 않고 producer가 secret-free atomic snapshot을 발행하게 한 뒤, consumer가 release·boot·freshness·권한을 다시 검증하면 관측 편의와 권한 격리를 함께 유지할 수 있다.
- 전략상 후보 없음과 시장 데이터 결측은 서로 다른 결과다. 전자만 관망 표본으로 기록하고 후자는 구체 오류와 누락 coverage로 남겨야 시뮬레이션 완주율이 데이터 장애를 숨기지 않는다.
- launchd plist를 전환할 때는 array item 치환 성공을 가정하지 않고 최종 `ProgramArguments` 길이와 wrapper 하나만 남았는지를 다시 검증한다.
- OAuth client를 주기 loop마다 새로 만들면 유효 token을 불필요하게 교체한다. 같은 설정에서는 client/token을 메모리에서 재사용하고 `invalid_client`는 credential 변경과 재시작 전까지 terminal 상태로 다뤄야 한다.

### 검증 범위

- 사용자 slash interaction, 로컬·Mac non-live gate, 새 status artifact와 세 LaunchAgent의 동일 release를 검증했다. 실제 주문, 수익성, news·watchdog 설치, exact-five 운영 완료의 근거는 아니다.
- OAuth 수정은 Windows 전체 회귀와 non-live gate, Mac network-denied gate를 통과했다. 실제 Toss 인증 성공은 새 client credential의 비노출 one-shot 검증 전까지 미완료다.
