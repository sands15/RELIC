# 2026-09-27

- [[Projects/Evelyn]]: 실제 음성 사용 경로에서 Windows와 Docker가 같은 bind mount를
  서로 다른 root identity로 계산해 안전 검사가 답변을 막는 것을 확인했다. 검사 자체를
  끄지 않고, 선언된 공유 경로만 같은 identity로 묶고 다른 root는 계속 거부하도록 했다.
- 회귀와 실제 양쪽 runtime의 경계값·읽기 검사는 통과했다. UI의 출력 테스트와 마이크
  중지·재개도 확인했다. 수정 후 새 실제 음성 턴의 완주와 사람의 청감은 아직 별개다.
- 재사용할 배움: cross-runtime 안전 경계는 각 OS의 절대경로가 아니라 검증된 공유
  자원의 논리 identity로 결박하고, 기존 fail-closed 검사를 유지한 채 양쪽에서 확인한다.
  원본 근거: Evelyn `docs/worklog/2026-09-27.md`,
  `docs/MEMORY_PROVENANCE_DELETION_CONTRACT.md`.
- [[Projects/Evelyn]]: 음성 답변의 화면 표시는 생성 직후 임시로 앞당기고,
  영속 기록은 실제 재생 확인 뒤에만 확정했다. 관련 회귀와 한 실제 발화의
  화면 전환을 확인했다. 재사용할 배움은 사용자에게 빠르게 보여주는 상태와
  외부 전달이 완료된 상태를 분리하는 것이다. 원본 근거: Evelyn
  `docs/worklog/2026-09-27.md`.
- [[Projects/Evelyn]]: 현재 창 가림 검사에서 화면에 그려지지 않는 DWM-cloaked
  보조 창을 실제 가림으로 오인하는 경로를 확인하고, 실제 겹침·DWM 판정 불명은
  계속 거부하는 source 회귀를 추가했다. 재사용할 배움은 창의 visible 플래그와
  실제 합성 여부를 구분하되 불명 상태는 fail-closed로 남기는 것이다. 앱의 새
  실제 화면 반응은 아직 미검증이다. 원본 근거: Evelyn
  `docs/worklog/2026-09-27.md`, `evelyn_core/runtime/evelyn_core/vision_monitor_capture.py`.
- [[Projects/Evelyn]]: 로컬 종료 요청은 접수됐지만 정리 helper가 소유 프로세스의
  Job 종료에 함께 묶여 실제 서비스 종료 전에 사라지는 문제를 고쳤다. 격리
  회귀와 실제 종료 상태를 각각 확인했다. 재사용할 배움은 종료 owner보다 오래
  살아야 하는 helper의 수명을 명시적으로 분리하고, 요청 ACK가 아닌 최종
  자원 상태로 성공을 판정하는 것이다. 원본 근거: Evelyn
  `docs/worklog/2026-09-27.md`, `evelyn_core/runtime/evelyn_core/windows_process_job.py`.
- [[Projects/Evelyn]]: 선제 대화가 이전 답변을 재사용하는 경로에서 기억 삭제
  검증과 사용자·브리지 귀속을 Main 요청과 발화 전달까지 확인하도록 소스를
  보강했다. 후속 회귀에서 저장 실패 시 현재 프로세스의 완료 대화만 소유자별로
  이어가고, 비동기 답변은 큐 수락이 아닌 실제 software playback 확인 뒤에
  기록하도록 했다. 비동기 행동의 후속 음성도 입력 당시 소유자가 없거나
  바뀌면 큐에서 거부하도록 했다. 재사용할 배움은 생성·큐 수락·전달 완료를
  서로 다른 경계로 다루고 각 단계에 원래 소유자를 묶어야 한다는 것이다.
  이미 꺼낸 요청도 예열 뒤와 첫 출력 직전에 소유권을 재확인했다. 비정상 중복
  브리지의 원자적 전환과 실제 청감은 미검증이다. 원본 근거: Evelyn
  `docs/worklog/2026-09-27.md`, `evelyn_core/runtime/evelyn_core/local_io_bridge.py`.
