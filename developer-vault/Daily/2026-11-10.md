# 2026-11-10

## Evelyn Mind — 컨테이너 안의 마음은 PC를 읽지 못한다, 그리고 "빼기"보다 "자리표시"

이블린이 매 턴 시각을 알고, 물으면 PC 정보를 로컬에서만 답하게 했다. 설계가 승인된 뒤 계획을 쓰려고 코드를 읽다가 전제 두 개가 틀린 것을 찾았다.

- 마음은 Docker 컨테이너에서 돈다. 그래서 거기서 OS와 이름을 읽으면 컨테이너의 Linux 정보가 나온다. PC 정보는 PC에서 직접 도는 몸(body-local)이 연결 인사(`hello`) 때 알려 주게 바꿨다.
- 비밀 답을 기록에서 그냥 빼면, 다음 턴 모델은 답 없는 질문만 보게 된다. 그러면 작은 모델이 답을 지어낼 수 있다. 그래서 답이 있었다는 자리표시만 남겼다.

배운 점은 세 가지다.

- 값을 "어디서 읽느냐"는 실행 위치(컨테이너인지 호스트인지)부터 확인한다.
- 프롬프트에서 무언가를 숨길 때는 빈자리가 모델에게 어떻게 보일지도 설계한다.
- prefix cache를 지키려면 바뀌는 값(시각)은 프롬프트 맨 끝 메시지에만 둔다.

또 Python 3.11의 `platform.release()`는 Windows 11에서도 "10"을 돌려준다. 그래서 빌드 번호(22000 이상)로 구분해야 한다.

증거 수준: source 시험(좁은 회귀 1524개 통과)과 body-local 인터프리터에서 한 실제 읽기다. 실제 기동과 음성은 미검증이다.

## Evelyn Mind — 말로 하는 행동은 묻고, 확인받고, 한 번만 실행한다

채팅 앞단의 낱말 검사가 일상 말을 명령으로 잡았다(예: "마인크래프트 재밌었는데 이제 나가볼게"가 실제로 접속을 끊음). 앞단은 `/명령`만 실행하게 줄였다. 나머지 행동은 마음이 알아듣고, 정해진 질문을 하고, 소유자의 "응"을 받은 뒤 Bot API에 실행을 요청한다. 재시작·종료는 동사를 다시 말해야 한다. 말 행동 스위치는 실제 Router 측정을 통과할 때까지 꺼 둔다.

배운 점은 네 가지다.

- 실행을 요청한 쪽의 작업 안에서 행동을 돌리면, 연결이 끊길 때 그 작업과 함께 취소된다. 그러면 같은 요청이 다시 와서 재시작이 두 번 나갈 수 있다. 행동은 따로 작업으로 돌리고, 요청한 쪽은 그 작업을 `shield`로 기다린다.
- 정해진 문장도 실제 서비스의 안전 검사를 통과하는지 시험한다. "다시 시작할게."는 "확인 안 된 일을 했다는 말" 검사에 걸려, 재시작 직전에 "다시 물어봐 줄래?"로 바뀌었다.
- 앞단의 실행 경로를 지우면, 그 말은 도구가 없는 대화 모델로 간다. 그러면 대화 모델이 "껐어"라고 거짓으로 답할 수 있다. 대화만으로는 행동이 일어나지 않는다는 한 줄을 프롬프트에 고정으로 넣었다.
- 판정 품질을 잴 시험 문장은 프롬프트를 보지 않은 사람이 쓰고, 재기 전에 고정한다. 첫 묶음은 너무 쉬워서, 재기 전에 어렵게 다시 썼다.

증거 수준: source 시험만 했다. 전체 7575개 통과(370997a8), 최종 수정 뒤 마음 묶음 1172개 통과(ae68fc34). Router 측정과 실제 마이크·재시작은 미실행이다(Docker가 꺼져 있었음). 브랜치 `feat/mind-confirmed-actions`는 실험 브랜치에 아직 합치지 않았다.

다음 확인: 소유자가 병합을 허락하면 합친다. 이블린을 켠 뒤 고정한 문장으로 한 번 재고, 통과할 때만 스위치를 켠다.
