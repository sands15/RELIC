## 이미지 검증과 실제 행동 검증 구분

- 현재 소스로 이미지를 다시 조립하고 내부 파일·설치 의존성·회귀 검사를 대조했다. 이미지 검사가
  통과해도 실제 행동 검사는 실패할 수 있다. 종료 후 상태만으로 원인을 추정하지 않고 실패 순간의
  조건을 구분해야 하며, 원인 미확정 결과와 정상 정리를 성공 판정에서 분리한다.
- 실패 판정에 사용한 순간의 조건만 작은 진단으로 보존하도록 보완·회귀 검증했다. 진단 파일 자체가
  손상돼도 원래 종료·정리 흐름을 막지 않아야 한다. 진단 추가는 실제 실패 해결의 증거가 아니다.
- 동일한 원자 교체 코드를 사용해도 공유 파일시스템 경계의 읽기는 별도 검증이 필요했다. 실제 실패의
  읽기 오류를 합성 검사에서 재현했고, 내부 저장소 대조·강제 저장 대조로 해결되지 않는 조건을 구분했다.
- 실시간 상태를 내부 파일시스템으로 분리한 뒤에도 실제 행동과 권한 확인은 별도로 실패했다.
  고정 오류 코드 하나가 파일 누락·손상·읽기 실패·실제 소유자 불일치를 함께 뜻할 수 있으므로,
  원문을 저장하지 않는 진단에서도 실패 순간의 원인 분류를 보존해야 한다. 정상 정리와 기능 성공은 별개다.
- 실제 설치 라이브러리의 오프라인 대조에서 로컬 예측 이벤트만으로 완료와 검색 결과가 바뀌는 경로를
  재현했다. 합성 조건의 인과 재현과 실제 실행의 원인 확정은 다르며, 정상 취소·늦은 서버 정정도 함께 확인한다.
- 중간 재시도 실패와 최종 성공이 한 결과문에 섞이면 실패 단어 검색이 성공한 행동까지 실패로 분류할 수
  있음을 실제 판정 코드로 재현했다. 복구 성공·최종 실패를 함께 대조하고, 원래 실사용 실패와의 인과는 별도로 증명해야 한다.
