### 결과

- Mindcraft P1-2A-1의 source/offline 보완을 구현했다. 실제 overlay lock의 `undici`를 7.29.0으로
  갱신하고 root와 overlay 모두를 검사하는 CI high gate를 추가했다. production audit 결과는 root
  moderate 8·high 0·critical 0, overlay moderate 15·high 0·critical 0이었다.
- Mineflayer private `_client.write` packet override를 삭제하고 테스트 경로를 checkout에 독립적으로
  바꿨으며, Docker 검증이 POSIX shell wildcard로 전체 테스트를 전달하도록 고정했다. pinned source와 patch를
  순서대로 합성한 Node 22 환경에서 311/311과 runtime verifier 3개, Python Mindcraft 36/36 및
  Minecraft 271/271을 통과했다. canonical unittest도 5,144 tests, 8 skipped, 실패 0으로 끝났다.
- Mineflayer P1-6 길찾기는 기존 2.4.5 engine을 유지하면서 실제 command mapping, 단일 progress-aware
  stuck owner, exact-owned fallback 1회와 문·덩굴·용암 보정을 source/offline으로 구현했다. 전용 조립
  회귀 211/211, Python 계약 49/49와 canonical 5,160 tests(8 skipped)가 통과했으며 Docker image와
  Minecraft live는 실행하지 않았다.
- P1-3C evaluator는 broker endpoint, request kind, memory mode, timeout, 전체 runtime source와 model
  artifact를 하나의 binding으로 묶고 parent가 signed child를 다시 계산하도록 보강했다. 영향 회귀
  276 tests와 canonical 5,248 tests(10 skipped)가 통과했고 실제 Qwen/Docker/GPU는 실행하지 않았다.
- 후속 승인된 Mindcraft P1-2B는 same-attempt readiness와 단일 restart owner, transactional start와
  exact-owned process cleanup을 구현했다. 실제 조립 image의 전체 Node 회귀·검증기·보안 감사와
  격리된 인증 접속·종료를 통과했다. 전체 식량 행동·장애 주입 검증은 별도 결과로 관리한다.

### 재사용 가능한 배움

- dependency gate는 편의상 둔 root lock이 아니라 실제 배포를 조립하는 각 lock을 직접 검사해야 한다.
  프레임워크가 이미 보장하는 packet tick을 private API로 다시 감싸기보다 중복 override를 없애는 편이
  더 작고 손실 없는 수정이다.
- 길찾기는 최종 도착만으로 품질을 증명할 수 없다. path·partial·stuck·timeout·recovery churn을 수치
  상한으로 함께 판정해야 오래 헤맨 뒤의 우연한 성공을 통과시키지 않는다.
- 평가기가 선언한 설정 digest와 실제 서버가 관측한 runtime identity는 다른 증거다. 자동 승격은
  served model/source/endpoint/kind/memory/timeout을 request-bound receipt로 받아 전·중·후 동일성을
  독립 검증할 때까지 닫아 두는 편이 안전하다.
- 테스트용 실행 제한도 클라이언트 상태를 오염시킬 수 있다. 서버가 거부한 동작을 클라이언트가
  낙관적으로 반영하는 경우에는 제품에 재시도를 더하기 전에 fixture의 권한 전환 시점을 확인한다.
- 동작 primitive의 존재와 실제 기본 목표 정책에서의 사용 가능성은 별개다. 소스 검토로 두 경계를
  구분했으며, 동료형 에이전트의 제품 목표를 공동 탐험으로 설정하고 구조 개입·공동 결과를 측정하는
  설계안을 작성했다. 목표 의도는 유지하되 중단된 실행 함수와 권한을 복구하지 않는 경계를 둔다.
  상세 설계는 사용자 검토 전이며 구현·live 완료 주장이 아니다. 원본은 아래 프로젝트 설계서다.
- 자발 발화 경로도 UI·출력 배선과 문맥 기반 후보 선택을 따로 확인해야 한다. 호출 경로가 있어도
  삭제 최신성 검증이 없는 질문 큐는 의도적으로 닫힐 수 있다. 소스 감사이며 실제 발화 검증은 아니다.
  상세 근거는 프로젝트의 같은 날짜 worklog `Everyday proactive speech` 절에 남겼다.
- `기억 미사용` 표시는 모든 입력 출처의 귀속을 증명하지 않는다. 선제 질문 설계에서는 직접 입력,
  원본 소유권, 전달 시도와 전달 확인을 구분하고 기존 삭제·발송 경계를 재사용했다. 설계 제안이며
  구현·live 결과는 아니다. 상세 계약은 프로젝트 P1-8 원본에 둔다.
- 기능 사용 동의의 지속성과 실행 권한의 수명은 분리할 수 있다. P1-8은 한 번의 동의 뒤 대기하되
  재시작 때 좁은 권한을 새로 검사하고 옛 실행은 복구하지 않도록 설계를 변경했다. 사용자에게 내부
  권한 갱신을 반복 관리시키지 않는 제품 방향이며, 구현·장기 운용 검증과는 구분한다.

  목표 저장·구현·검증·수정·재검증·목표 대조·완료까지 하나의 흐름으로 명시했다. 처음 승인한 범위의
  수정과 검증은 계속하며, 목표·범위·완료 기준을 바꾸는 결정은 다시 승인받는다.
- 목표·현재 상태·검증 근거·다음 행동은 기존 프로젝트 문서 한 곳에서 관리하고, 재개 시 실제 상태와
  대조한다. 완료는 각 필수 기준의 충족 근거로 판정하며 미검증 항목은 완료로 바꾸지 않는다.

  자동 적용과 실제 구현·실패 복구 흐름은 별도 검증이다.

  판단을 확인했다. 기존 대화·다른 호스트의 소급 적용이나 장기 개발 품질까지 검증한 것은 아니다.
