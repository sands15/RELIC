# 2026-09-01

## [[Projects/Toss Trading Bot|Toss Trading Bot]]

### 결과

- 새 paper experiment 전용 고정 A/B 두 레인을 로컬 코드에 구현했다. 총 가상현금 50:50, 레인 간 이체 금지, 서로 다른 최대 두 종목과 원자적 cohort, 종목별 독립 원장을 유지하고 한 종목만 적격인 날은 나머지 레인을 `NO_CANDIDATE`로 남긴다.
- 실제 계획 종목만 담는 news context와 단일 WebSocket exact-topic 구독, 레인별·합산 portfolio와 distinct session을 구분하는 status, 장 종료 restore-set maintenance와 단일 채널 redacted watchdog 알림을 함께 보강했다. cross-DB 복구는 기존 backup 세대를 먼저 무효화하고, retention은 완성된 DB 세트에만 적용하며 삭제 의도를 DB snapshot 밖에 남긴다. 세 ledger는 경로·inode·canonical schema·FK를 초기화 전에 검증하고, 로그 회전은 OS lock·durable journal과 gzip/raw 동반 세대로 중단 및 late-write를 복구한다.
- Discord `/현황` 조회를 허용 채널의 모든 비봇 사용자에게 열되, 계획 승인 버튼과 modal의 지정 사용자 제한은 분리해 유지했다. 자동 회귀와 Mac side-by-side 검증 뒤 approval job만 전환했으며, 다른 사용자 계정의 실제 UI 확인은 남겼다.
- `/현황` 장애를 writer/reader release 불일치와 안전 정지 뒤 stale status로 분리하고 planner·approval을 같은 exact SHA로 공동 전환했다. strict status 조회와 Discord Gateway는 복구됐고 planner는 현재 인증 차단을 `DEGRADED`로 표시한다. 유효한 별도 OAuth client가 준비되기 전까지 stream은 비활성화했으며 실주문과 credential 재발급은 수행하지 않았다.
- 맥북에서도 같은 이력을 이어 작업할 수 있도록 현재 작업 브랜치의 로컬 선행 커밋을 GitHub에 동기화하고 로컬 임시 산출물을 추적 대상에서 제외했다. 변경 영역 회귀와 공개 전 비밀정보·대용량 파일 점검을 통과했고, 원격 브랜치가 로컬 exact SHA와 일치함을 확인했다.
- 기기별 Codex 세션 저장소를 복사하지 않고, 트레이딩 봇에 한해 Mac을 단일 실행 호스트로 두었다. 기존 장문 대화는 pagination 제한으로 Handoff하지 못해 핵심 맥락을 새 원격 세션에 넘겼고, clean 전용 worktree가 작업 브랜치 exact SHA에 있음을 확인했다. SSH 로그인 셸에는 `codex`와 `codex-code-mode-host`를 모두 노출해 원격 명령 실행까지 검증했으며 기존 작업 트리는 건드리지 않았다.

### 재사용 가능한 배움

- 병렬 전략의 구독 수는 설정한 레인 수가 아니라 그날 실제로 잠긴 계획 종목 수에서 파생해야 불필요한 시장 데이터와 잘못된 장애 판정을 막을 수 있다.
- 같은 ranking snapshot에서 나온 두 거래는 거래 건수에는 각각 포함해도 시장 표본 수에는 같은 날짜 한 번만 포함해야 결과를 과대해석하지 않는다.
- backup은 개별 파일이 아니라 같은 날짜의 DB restore set으로 관리해야 중간 실패와 보존 정책이 복구 가능 날짜를 갈라놓지 않는다. 세대 원장을 읽을 수 없을 때는 기존 완료본을 미완료로 추측하지 말고 모든 교체·보존을 중단해야 한다. watchdog도 알림 목록을 먼저 저장하고 성공 건별로 확인해야 부분 전송 실패가 앞선 알림을 중복시키지 않는다. 같은 host의 watchdog은 외부 deadman을 대신하지 못한다.
- 프로세스 생존과 DB 무결성만으로 기능 readiness를 판단하면 인증 장애를 숨긴다. 운영 실패 blocker는 heartbeat에 반영하되 계획 시각 전·휴장 같은 정상 fail-closed 결과는 장애에서 제외해야 한다. 한 client의 새 token이 이전 token을 폐기하는 API에서는 독립 프로세스가 OAuth client를 공유하지 않게 강제하는 편이 비밀 token IPC보다 단순하고 안전하다.
- SQLite 파일 분리는 문자열 경로 비교만으로 부족하다. symlink·hardlink·foreign schema를 첫 write 전에 거부하고 device/inode, schema constraint, FK integrity를 함께 검증해야 독립 ledger라는 가정이 유지된다.
- rename 뒤 gzip하고 원본을 바로 지우는 로그 회전은 crash와 이미 열린 writer에 취약하다. 단일 writer lock, 단계별 durable journal, 압축 세대와 함께 보존되는 raw inode가 있어야 재시작과 late append를 데이터 유실 없이 다룰 수 있다.
- Codex SSH 원격 호스트는 CLI 본체만 PATH에 있어도 세션 생성은 가능하지만 명령 실행은 별도 code-mode host 부재로 실패할 수 있다. 앱 번들의 두 실행기를 로그인 셸 PATH에서 각각 검증해야 하며, 장문 pagination 대화는 요약된 새 원격 세션으로 넘기는 것이 현재의 안전한 우회다.
