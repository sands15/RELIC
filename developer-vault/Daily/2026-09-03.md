# 2026-09-03

## [[Projects/Evelyn|Evelyn]]

### 결과

- 개인 Local Voice의 목표를 마지막 음성 뒤 300ms soft endpoint와 추가 500ms reopen으로 동결했다.
  grace 안 재입력은 같은 PCM·ASR session의 한 발화로 처리하며, 현재 500ms hard endpoint는 구현·검증
  전까지 유지한다.
- 300ms 시점의 계산은 side-effect-free prepare로 제한하고, authoritative final과 exact binding이
  일치할 때만 accepted user turn을 승격하도록 했다. 구현·테스트·실제 장치 검증은 후속 범위다.
- 단기 제품 목표를 단일 PC의 로컬 방송 MVP로 전환했다. 기존 Control Page·Live2D·Local TTS를
  재사용한 3턴 비공개 OBS 녹화를 첫 checkpoint로 두고, 마이크와 외부 플랫폼 연동은 분리했다.
- 대량 방송 채팅은 LLM에 건별 전달하지 않고 bounded user slot·중복 군집·RRF 뒤 답할 한 건 또는
  침묵으로 축약하며, 첫 플랫폼을 CHZZK 공식 read-only user session으로 동결했다. 구현·OAuth·live
  실행은 아직 하지 않았다.
- 기본 OFF의 context-free local chatter를 exact Control Page 명령과 별도 speaker grant로 구현했다.
  사용자 입력·권한 만료/교체가 기존 발화를 선점하며 source/offline 전체 회귀를 통과했지만 실제
  speaker 청취, 재미·상황 적합성과 방송 준비는 검증하지 않았다.
- 기존 Background Vision Watch 결과가 일반 turn에서 사라지던 문맥 연결을 복구했다. local Control
  Page에만 fresh scene을 untrusted soft context로 전달하고 Discord·voice·autonomy·chatter와 exact OCR은
  분리했다. source/offline 회귀는 통과했지만 실제 화면 인식 품질과 방송 상황 인식은 검증하지 않았다.
- 지정된 community DNA3.0 9B Q8_0를 설치하고 같은 llama.cpp·RTX 5090·synthetic workload에서
  generation `137.57 tok/s`를 확인했다. 기존 Gemma 4 12B IQ4_XS의 `147.03 tok/s`보다 6.43% 낮았지만,
  양자화와 checkpoint 출처가 달라 모델 구조나 품질의 우열로 승격하지 않았다. 별도 장문 생성에서
  GPU decode 사용률은 평균 94.27%, 중앙값 95%였다. baseline 정규화 VRAM은 DNA가 Gemma보다
  loaded-idle 기준 1.29 GiB 적었다. 10개 deterministic 답변 체크는 DNA 31/41, Gemma 33/41이었지만,
  양자화·SWA 동작이 다르고 문항별 1회뿐이라 모두 단일 effective-runtime 표본으로 제한했다.
- Evelyn의 exact tool 요청을 모델 없이 닫고 독립 local read만 bounded wave로 묶는 candidate를 구현해
  source/offline 전체 회귀를 통과했다. 실제 모델·서비스 A/B는 실행하지 않았으며 production은 기존
  직렬 경로를 유지한다.
- 실행 가능한 Voyager·port-3000 bridge와 host fallback을 제거하고 Minecraft 실행 경로를 Docker
  Mindcraft 하나로 좁혔다. 기존 호환 이름은 그 경로만 가리키며 실제 Docker·Minecraft는 시작하지 않았다.

### 재사용 가능한 배움

- 비동기 요청 취소는 이미 기록되거나 외부로 전달된 효과의 rollback이 아니다. 늦은 입력을 합치는
  최적화는 계산 단계와 commit 단계를 분리하고, 재입력에는 임시 계산만 폐기해야 한다.
- 같은 GPU·runtime·token count만으로는 모델 비교가 완전히 공정해지지 않는다. 양자화, checkpoint
  revision과 microbenchmark/E2E 범위를 결과 옆에 함께 고정해야 숫자를 재사용할 수 있다.
- 도구 호출 최적화는 성공 경로의 속도만 재면 부족하다. deadline·부분 실패에서도 실제 호출 receipt가
  빠짐없이 남고, 평가 출력이 입력 artifact를 덮어쓰지 않는지까지 같은 승격 gate로 검증해야 한다.
- dependency release gate는 편의상 둔 root lock이 아니라 실제 image를 조립하는 manifest·lock·patch와
  전체 image test를 따라야 한다. process 재시작도 계층마다 두지 말고 generation owner 하나가 맡아야 한다.
- 레거시 제거는 실행 entry·listener·fallback을 0으로 만들고, 아직 쓰이는 호환 이름이 현재 backend만
  가리키는지를 회귀로 고정하면 대규모 이름 변경 없이도 일방향으로 만들 수 있다.
