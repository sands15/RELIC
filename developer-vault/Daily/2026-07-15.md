# 2026-07-15

## [[Projects/Evelyn|Evelyn]]

### 결과

- 전체 감사를 바탕으로 기능 추가보다 복구 기준점, 보안 경계와 회귀 기준선 고정을 우선했다.
- 복구 checkpoint와 tag를 고정하고, Control Page의 loopback Host/Origin·CSRF·JSON 변경 요청 경계를 실행 서비스에 반영했다.
- 실제 `main.py` process smoke를 포함한 950개 회귀를 실패·오류·건너뜀 없이 통과했다.
- 음성·런타임 보존 정책을 적용하고 승인된 정리로 약 542.7 MB의 기존 후보를 제거했다. Minecraft 의존성은 강제 override 없이 high finding을 4개에서 0개로 낮췄다.

### 증거 범위

- `local live`: Control Page의 정상 요청과 외부 Origin·누락 CSRF·비 JSON 요청 차단, 제한된 서비스 재배포와 healthy 상태를 확인했다.
- `source/offline`: 회귀, 의존성 설치·감사와 보존 정책 검증을 통과했다.
- `external 미검증`: 실제 Discord 음성 및 Minecraft 접속·로그인·인게임 행동은 실행하지 않았다.

### 재사용 가능한 배움

- 보안 변경은 소스 테스트만으로 완료되지 않는다. 실제 배포 경계에서 허용 요청과 거부 요청을 함께 확인해야 한다.
- 감사에서 기능 수보다 복구·보안·회귀의 약한 고리를 먼저 고정하면 이후 변경의 신뢰 기반이 생긴다.
