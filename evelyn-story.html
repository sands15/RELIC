Project Story

Evelyn Voice AI Assistant

한국어 음성 대화 캐릭터를 목표로, STT, LLM, TTS, memory, playback을 하나의 흐름으로 연결한 개인 AI assistant 프로젝트입니다.

GitHub Back to Projects

START

왜 만들었나

단순히 텍스트로 답하는 챗봇보다, 실제로 말을 듣고 목소리로 반응하는 캐릭터형 AI를 만들고 싶었습니다. Evelyn은 모델 하나를 테스트하는 프로젝트가 아니라, 사용자의 입력부터 응답 재생까지 이어지는 전체 시스템을 직접 연결해보는 실험입니다.

이 프로젝트를 통해 관심사는 더 분명해졌습니다. 좋은 AI 경험은 모델 성능만으로 만들어지지 않고, 입력 처리, 라우팅, 기억, 음성 출력, 지연 관리가 함께 맞물려야 합니다.

FLOW

시스템 흐름

Evelyn은 음성 입력을 받아 텍스트로 바꾸고, LLM 응답을 생성한 뒤, 다시 음성으로 출력하는 흐름을 중심으로 구성했습니다.

Voice Input STT Routing LLM Memory TTS Playback

직접 다룬 부분

  • STT, LLM, TTS, playback 단계가 하나의 turn으로 이어지도록 연결
  • 고정 응답과 일반 응답을 나누는 routing 흐름 정리
  • 캐릭터 응답과 memory 흐름을 점검하며 대화 일관성 개선
  • turn_trace 로그를 기준으로 지연 구간을 측정하고 개선 기준선 정리

RESULT

성능 기준선

기존의 STT 완료, 첫 음성 출력, 전체 턴 기준선 대신 실제 체감 시작점인 첫 토큰과 첫 PCM 기준으로 다시 정리했습니다.

31ms 첫 토큰 보통 EXAONE 10회 중앙값
618ms 첫 PCM 보통 OmniVoice 10회 중앙값
65.8x Main LLM 개선 Gemma E4B 2.04s -> EXAONE 31ms

EXAONE은 streaming SSE의 첫 non-empty token까지, TTS는 OmniVoice streaming PCM의 첫 audio chunk까지를 측정했습니다. STT와 Discord playback 지연은 이 블록의 수치에 포함하지 않았습니다.

배운 점

Evelyn을 만들면서 AI 서비스의 품질은 답변 내용뿐 아니라 응답까지 도달하는 전체 흐름에서 결정된다는 것을 배웠습니다. 특히 음성 AI에서는 작은 지연도 사용자 경험에 크게 느껴지기 때문에, 로그를 남기고 병목을 나누어 보는 과정이 중요했습니다.

다음 개선 방향

  1. cached audio fast path와 문장 단위 TTS로 첫 음성 출력 지연 줄이기
  2. Obsidian식 memory 구조를 연결해 장기 맥락 유지 개선
  3. agent 구조를 확장해 대화뿐 아니라 행동 실행까지 이어지는 흐름 실험
