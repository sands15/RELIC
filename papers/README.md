# 논문 리뷰 원본

RELIC 작성 화면의 ‘GitHub에 저장’으로 `<리뷰 주소>.json` 파일을 이 폴더에 반영한다. 글마다 파일 하나를 사용하며 기존 글 수정은 주소와 최초 발행일을 유지한다. 파일로 공개 준비한 뒤 GitHub에 직접 업로드하는 방식도 사용할 수 있다.

작성 화면은 GitHub의 계정과 저장소 소유자를 확인해 `sands15`만 허용한다. GitHub 로그인과 재방문 유지 기능은 Cloudflare Workers를 [최초 연결](../auth/paper-reviews/README.md)한 뒤 사용할 수 있으며, 현재 실제 서비스 연결은 미완료다. 연결하면 서버가 인증과 고정 저장 경로를 검증하고 같은 브라우저의 로그인은 최대 8시간 유지한다. 초안은 브라우저에만 보관한다.

기존 토큰 연결 경로도 유지한다. GitHub에서 fine-grained 토큰을 만들 때 저장소는 RELIC만 선택하고 Contents 권한을 Read and write로 설정한다. 실제 토큰은 작성 화면의 접힌 ‘기존 토큰으로 연결’ 안에 있는 암호 입력칸에만 입력한다. 이 방식의 토큰은 페이지 메모리에서만 사용하고 로그아웃·페이지 종료 시 지워지며 초안과 공개 파일에 포함되지 않는다.

카테고리는 처음에 비어 있다. 작성 화면에서 이름을 입력하고 ‘추가’를 누르면 루트의 `paper-review-categories.json`에 반영한다. 중복 이름은 다시 추가하지 않으며 사이트 배포 후 공개 목록에도 나타난다. 카테고리 글 수가 0이어도 직접 추가한 이름은 표시된다. 기존 리뷰에서 사용한 카테고리도 읽기 목록에서 유지한다.

- 작성: [RELIC 논문 리뷰 작성](https://sands15.github.io/RELIC/paper-review-write.html).
- 최종 반영: [GitHub 파일 업로드](https://github.com/sands15/RELIC/upload/main/papers). 저장소 쓰기 권한이 필요하다.
- 공개된 파일만 이 폴더에 저장한다. `.draft.json` 백업 파일과 개인 메모는 업로드하지 않는다.
- `index.json`은 공개 목록용 파생 데이터다. 배포 시 `tools/build-paper-reviews.py`가 각 리뷰 원본을 검사하고 목록을 생성하므로 직접 관리하지 않는다. 저장소의 초기 값 `[]`는 아직 공개 글이 없는 상태다.
- 파일 형식 오류는 배포를 중단한다. 기존 공개 배포는 유지되며 오류를 수정한 뒤 다시 반영한다.
- 직접 저장은 GitHub 파일의 기존 버전(SHA)을 비교하며 다른 기기의 수정과 충돌하면 덮어쓰지 않는다. 현재 입력을 백업하고 ‘GitHub 최신 글 가져오기’로 최신 원본을 불러온 뒤 수정한다. 오래된 버전 정보가 없는 기존 초안도 최신 글을 가져와야 직접 덮어쓸 수 있다.
- 저장 응답이 불확실하면 입력을 유지한다. 같은 내용을 다시 저장할 때 기존 원본을 먼저 재읽고 이미 반영된 내용이면 추가 저장을 하지 않는다. 저장 중 입력한 새 내용도 유지하며 별도로 다시 저장하도록 안내한다.

GitHub 반영 후 Pages 배포가 완료되어야 공개 목록에 나타난다. ‘사이트 반영 확인’은 실제 공개 글과 목록의 내용을 비교한다. GitHub 저장과 사이트 반영을 구분하며 다운로드·임시저장만으로는 발행되지 않는다.
