## 승인 범위와 미결 사항

페이지 신설, RELIC 진입 링크, 최신순 목록, 상세 읽기, 작성 기능이 요청되었다. 사용자가 제시된 기능 범위와 함께 GitHub 최종 공개 방식을 선택했다. 이를 구현 범위로 기록하고 필요한 구현·수정·검증을 수행한다. 이후 지정한 블로그 목록 배치와 RELIC 스타일 통일을 적용한다. 공개 운영 배포는 최종 결과를 제시한 뒤 별도 승인한다.

권장안은 기존 GitHub Pages를 유지하고 RELIC에서 작성·임시저장·미리보기 후 GitHub에서 최종 공개하는 방식이다. 작성 화면은 공개 파일을 생성하고 GitHub의 로그인 및 저장소 쓰기 권한을 이용해 최종 반영한다. 브라우저 임시저장을 공개 발행으로 표시하지 않는다. 사용자에게 별도 서버 운영을 요구하지 않는 장점이 있으며, 최종 공개 시 GitHub 단계와 배포 시간이 필요한 제한이 있다.

사용자의 후속 요청 “그렇게 넣어봐”는 제시한 RELIC 저장소 전용 토큰 인증과 ‘GitHub에 저장’ 버튼 구현을 승인한 것으로 기록한다. 토큰은 현재 문서의 메모리에만 보관하고 입력칸·초안·파일·브라우저 저장 공간·기록에는 보관하지 않는다. GitHub Contents API로 `sands15/RELIC`의 `main`, `papers/<고정 주소>.json`에만 쓰며 기존 Pages workflow를 이용한다. 임시저장과 파일 공개 준비는 유지한다. 이 기능 구현 승인은 실제 인증정보 발급/입력, 검증용 글의 공개 발행이나 페이지 운영 배포 승인이 아니다.

직접 저장 검증: 공개 필드 검증과 UTF-8 전송, 인증/권한/네트워크 실패에서 입력 보존, 기존 파일 SHA를 이용한 오래된 수정·동시 변경 차단, 저장 중 입력/초안 전환 보존, 토큰 비보관을 확인한다. GitHub 저장 성공은 공개 저장소의 해당 내용 재읽기로 확인하며 사이트 배포는 별도로 표시한다. 배포 확인 버튼은 Pages의 글/목록 내용을 비교하고 workflow 상태를 확인한다. 실제 토큰 없는 환경은 합성 API의 오프라인 검사와 로컬 UI 근거로 구분하며 실제 GitHub 쓰기를 완료로 표시하지 않는다.

추가 요청: GitHub의 실제 계정 정보를 확인해 RELIC 소유자 `sands15`만 작성 화면과 저장을 사용할 수 있도록 한다. 공개 방문자와 다른 계정은 읽기만 가능하며 작성 화면은 인증 전 숨긴다. 앞서 선택한 토큰 인증을 사용하며 OAuth 로그인을 완료한 것처럼 표현하지 않는다. 기본 분야 7개를 제거하고 작성자가 직접 카테고리를 추가한다. 추가 카테고리 원본은 `paper-review-categories.json`이며 GitHub 쓰기의 두 번째 고정 경로로 한정한다. 기존 리뷰에서 사용하는 분야는 검색·읽기 경로에서 유지한다.

대안은 RELIC에서 작성자 로그인 후 즉시 발행하는 방식이다. 여러 기기의 초안 공유 및 직접 발행에 적합하지만 인증, 저장 서비스, 자산 업로드, 운영 책임을 새로 정해야 한다. 선택되면 정확한 서비스와 접근 범위를 제안하여 이 기록을 갱신한다. 미선택 서비스를 임의로 설치하거나 연결하지 않는다.

### 후속 요청: GitHub 로그인과 연결 유지

사용자는 Cloudflare Workers 무료 요금제와 작성·인증 화면을 함께 제공하는 구성을 선택했다. 구현은 기존 격리 작업본에서 수행한 뒤 최종 확인한 파일만 기존 미리보기에 반영한다. 로그인 유지 기본값은 GitHub App의 기본 토큰 유효시간에 맞춰 최대 8시간이다. 토큰은 서버 키로 암호화된 HttpOnly·Secure·SameSite=Lax 쿠키로만 사용하며 JavaScript, 초안과 브라우저 저장 공간에 넣지 않는다. 서버에서도 매 요청의 GitHub 계정·저장소 소유권을 확인한다. 만료·로그아웃 시 작성은 잠그고 입력/초안은 유지한다. 데이터베이스와 토큰 자동 갱신을 추가하지 않는다.

구현 순서: (1) `auth/paper-reviews/worker.mjs`의 OAuth state·PKCE·쿠키 및 서버의 고정 API 경계와 실패 검사를 먼저 작성, (2) 기존 모델·GitHub 저장 모듈을 재사용해 구현, (3) `assets/paper-review-session.js`와 기존 편집 화면에 로그인 복원·로그아웃 연결, (4) 최초 로그인 버튼에서 이전 주소의 브라우저 초안을 새 작성 주소로 전달하는 origin·창·nonce 검증과 중복 덮어쓰기 거부, (5) 표준 Node 빌더·Workers 설정·일회 연결 안내, (6) 합성 OAuth·브라우저 재방문/저장/만료/기존 초안 보존 확인과 같은 읽기 전용 검토자 재검토. 서버의 실제 GitHub 쓰기와 Pages 반영 검증은 실제 계정 연결·운영 반영 뒤 구분해 수행한다. 신규 로컬 패키지 설치나 공개 배포는 이번 소스 검증에 포함하지 않는다.

사용자가 매번 토큰을 연결해야 하는지 물은 뒤 “그렇게 넣는데 별도 인증 서버가 필요하다는게 무슨말이야”라고 요청했다. GitHub 로그인 버튼과 재방문 시 로그인 유지를 추가하는 의도는 승인된 범위로 기록한다. 현재 토큰 방식이 이미 OAuth 로그인이나 로그인 유지 기능을 제공한다고 해석하지 않는다. 실제 서비스 선택, GitHub 앱 등록·권한 부여와 운영 배포는 아직 완료되지 않았다.

선택한 구성은 Cloudflare Workers 무료 요금제의 작은 작성·인증 서비스다. 공개 목록·상세·원본은 기존 GitHub Pages/GitHub 저장소를 유지하고, RELIC의 작성 링크에서 같은 스타일의 클라우드 작성 화면으로 연결한다. 비밀키는 서버에서 처리하고 작성자와 고정 저장 경로를 검증한다. GitHub App 설치는 RELIC 한 개와 Contents 쓰기로 한정한다. 사용자는 Cloudflare 계정이 없어 새로 가입해야 한다고 답했다. 소스 구현은 승인 범위이며 실제 가입·앱 권한 부여·비밀정보 설정·운영 배포는 미완료다. 별도 도메인 구매, 유료 요금제, 데이터베이스, 여러 작성자와 초안의 클라우드 동기화는 포함하지 않는다.

작성 화면을 인증 서비스와 같은 주소에 두어 타사 쿠키에 의존하지 않는다. 새 작성 주소로 이전할 때 기존 초안은 검증된 창 연결로 같은 브라우저에 복사하며 원본과 중복 초안을 덮어쓰거나 지우지 않는다. 유지 기간은 최대 8시간, 로그아웃은 현재 브라우저 세션 종료다. 만료·인증 취소·다른 계정에서는 잠그고 현재 입력을 유지한다. 실제 운영 주소에서의 이전과 로그인은 아직 검증하지 않았다.

공식 근거: [GitHub 로그인 버튼과 GitHub App](https://docs.github.com/en/apps/creating-github-apps/writing-code-for-a-github-app/building-a-login-with-github-button-with-a-github-app), [OAuth 웹 인증의 비밀키 처리](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps), [Workers 무료 요금제와 제한](https://developers.cloudflare.com/workers/platform/pricing/), [Workers 비밀정보 보관](https://developers.cloudflare.com/workers/configuration/secrets/), [타사 쿠키 제한](https://developer.mozilla.org/en-US/docs/Web/Privacy/Guides/Third-party_cookies). 무료 사용의 실제 수용 여부는 선택한 최종 구현과 서비스 제한에서 확인하며 무제한 운영으로 약속하지 않는다.

## 화면 설계

### 1. 목록: `paper-reviews.html`

RELIC 주 메뉴의 '논문 리뷰' 링크로 진입한다. 페이지 상단에는 RELIC 복귀 링크, '논문 리뷰' 제목, 작성 진입 버튼이 있다. 큰 Hero나 애니메이션 없이 첫 화면에 글 목록이 보인다.

최종 지정 블로그를 참고한 텍스트 목록이다. PC 왼쪽에 작성자 정보와 분야/개수를 표시하고 오른쪽에는 리뷰 제목, 발행일, 짧은 요약, 클릭 가능한 태그를 표시한다. 썸네일 중심의 목록 대신 글을 읽기 편한 간격으로 배치한다. 대표 이미지는 선택적으로 상세 화면에 표시한다. 제목을 누르면 리뷰별 상세 주소로 이동한다.

기본 정렬은 리뷰 최초 발행일 내림차순이다. 논문 출판연도와 수정일은 정렬 기준과 구분한다. 날짜가 같으면 고정 식별자로 순서를 안정화한다. 제목·논문명·태그 검색, 분야 필터, 최신순/오래된순 선택, 페이지 이동을 제공한다. 필터 결과가 없는 상태와 아직 리뷰가 없는 상태는 서로 다른 안내를 표시한다.

PC에서는 분야 탐색과 글 목록을 함께 배치하고, 모바일에서는 목록 위에 탐색 항목을 배치한다. 모바일에서도 제목, 요약, 날짜와 작성 버튼을 사용할 수 있어야 한다.

### 2. 상세: 리뷰별 독립 주소

리뷰 제목, 발행일과 수정일, 분야·태그, 논문 정보와 원문 링크를 표시한다. 본문은 읽기 좋은 폭과 문단 간격을 사용하고 소제목 이동과 목록 복귀를 제공한다. 논문 출판연도는 논문 정보에 별도로 표시한다. 해당 리뷰의 공개 주소로 다시 방문할 수 있어야 한다.

### 3. 작성: `paper-review-write.html`

- 리뷰 정보: 리뷰 제목, 한 줄 요약, 분야, 태그, 선택적 대표 이미지와 설명.
- 논문 정보: 논문 제목, 저자, 발표연도, 학회/저널, DOI 또는 원문 링크, 선택적 코드 링크.
- 본문: 자유 편집과 논문 리뷰 틀 삽입. 기본 틀은 읽게 된 이유, 핵심 요약, 문제 정의, 방법론, 실험/결과, 장점과 한계, 개인 의견, 참고 자료다. 사용자가 틀을 바꾸거나 생략할 수 있다.
- 편집 보조: 소제목, 강조, 목록, 인용, 코드, 링크, 이미지/캡션 입력. 구체적 편집 구현은 선택된 저장 방식에 맞추며 원문 HTML의 무제한 실행은 허용하지 않는다.
- 미리보기: 저장될 제목·논문 정보·본문과 목록에 나타날 요약을 확인한다. 작성 화면에서 미리보기 후 돌아와도 입력을 유지한다.
- 초안: 자동 임시저장, 저장 시각/실패 표시, 재방문 복원, 초안 선택과 파일 백업/복원. 저장되지 않은 변경의 이탈 방지와 덮어쓰기 확인을 제공한다.
- 검증: 공개 준비 시 리뷰 제목, 논문 제목, 본문과 원문 링크를 점검한다. URL은 허용된 웹 주소만 사용하고 오류는 입력 위치에 표시한다. 선택 필드를 불필요하게 필수화하지 않는다.
- 공개: 임시저장과 공개 준비 버튼을 구별한다. GitHub 방식에서는 공개 파일 내보내기와 최종 반영 경로를 제공하고, 실제 배포 완료 전에는 '공개 완료'로 표시하지 않는다. 저장 실패 시 작성 내용은 유지한다.
- 직접 저장: ‘GitHub 연결’에서 저장소 전용 토큰을 현재 페이지 동안 사용하고 ‘GitHub에 저장’으로 공개 글을 반영한다. 연결 해제 시 즉시 지운다. 저장 중 이탈 경고, 인증/권한/충돌 안내, 저장한 내용 이후의 추가 입력 구별, 배포 확인과 GitHub/사이트 링크를 제공한다. 기존 글은 GitHub 최신 원본에서 SHA를 확보하며 SHA 없는 기존 초안은 최신 원본 가져오기 또는 파일 공개 경로를 이용한다.
- 수정: 기존 공개 글을 편집 입력으로 가져올 수 있고, 수정해도 최초 발행일과 고정 주소를 유지한다. 공개 글 삭제와 비공개 전환은 별도 요청이며 자동 수행하지 않는다.

## 권장안의 구현 단위

일반 HTML/CSS/JavaScript, Python 및 Node 표준 기능을 사용한다. 선택한 Workers 작성·인증 구현을 추가하며 로컬 신규 패키지는 설치하지 않는다. 별도 설계/계획 파일을 추가하지 않는다.

1. 읽기 경로: `index.html`의 진입 링크, `paper-reviews.html`, `paper-review.html?id=<고정 주소>`, `assets/paper-reviews.js`, `assets/paper-reviews.css`. 공개 원본은 `papers/<고정 주소>.json`이며 `tools/build-paper-reviews.py`가 배포 중 `_site/papers/index.json`을 생성한다. `.github/workflows/jekyll-gh-pages.yml`의 기존 Jekyll 공개 과정을 재사용한다. 원본과 목록을 이중 관리하지 않는다.
2. 작성 경로: `paper-review-write.html`, `assets/paper-review-editor.js`, `assets/paper-review-model.js`, `assets/paper-review-render.js`. 공개 원본과 같은 필드를 사용해 임시저장, 복원, 검증, 미리보기, 공개 파일 생성, 기존 글 수정 입력을 연결한다. 초안은 리뷰별 브라우저 저장 키를 사용해 다른 글과 분리하며 저장 시 이전 버전을 비교한다. 원문 HTML과 위험 URL은 실행하지 않는다. 지원 서식은 소제목, 강조, 목록, 인용, 코드, 링크, 이미지/캡션, 표이며 수식은 텍스트로 보존한다.
3. 통합 확인: 기존 포트폴리오 보존, 원본과 표시 결과의 대응, 목록·상세·작성 이동, 모바일 배치, 저장 오류 및 입력 보호를 검증한다. 구현하지 않은 읽기·작성·공개 단계를 완료로 표시하지 않는다. 초안 저장은 Web Locks의 같은 주소 잠금 안에서 읽기·버전 비교·쓰기를 수행한다. 한 화면의 중복 저장은 하나의 작업으로 합치며 최신 입력 저장 후 초안을 전환한다. 안전한 잠금을 제공하지 않는 환경은 파일 백업을 안내한다.

선택한 작성자 인증 외의 계정 시스템, 댓글, 방문자 작성, 좋아요, 조회수, AI 리뷰 생성, 자동 DOI 조회와 예약 발행은 범위 밖이다.

## 현재 확인과 한계

- 로컬 파일과 GitHub Pages workflow를 확인했다. 기존 사이트는 별도 글 저장/로그인 기능이 없는 정적 HTML 구조다.
- 공개 RELIC을 브라우저에서 열어 포트폴리오와 주요 메뉴를 확인했다. 신규 논문 리뷰 구현이나 배포의 근거는 아니다.
- graft 조회에는 사용 가능한 그래프가 없었다. 원본 HTML, 설정과 workflow를 직접 확인했다.
- 기존 미추적 사용자 파일은 유지했다. 신규 페이지를 로컬 구현했으며 운영 환경은 변경하지 않았다.
- 작성자 한 명이 사용하는 개인 리뷰 공간은 제안의 가정이다. 여러 방문자가 작성하는 기능은 포함하지 않는다.
- 개인 Vault에는 로컬 검증 결과만 간단히 기록한다. 공개 운영 완료나 실제 사용자 경험으로 확대하지 않는다.

## 다음 행동

승인된 직접 저장·소유자 인증·카테고리 추가의 로컬 구현과 검증·독립 검토·수정을 완료했다. 공개 운영 반영 대상은 `sands15/RELIC`의 기존 `main`/Pages workflow이며 사용자가 페이지·인증 코드 배포를 승인했다. 작성 서버는 실제 배포됐고 GitHub Client secret의 최초 입력만 남았다. 이 입력에 의존하지 않는 승인된 목록·상세·작성 페이지와 RELIC 메뉴부터 공개하고, `paper-review-auth.json`의 연결 주소는 서버 ready 확인 전까지 비워 둔다. 실제 인증정보는 사용자 서비스 화면에서 처리하고 대화·기록에 요청하거나 남기지 않는다.

후속 로그인 유지의 로컬 구현과 실제 App/Workers 배포는 아래 checkpoint에 기록했다. 새 인증키 발급·입력·제출은 브라우저 도구의 사용자 인계 규칙 때문에 직접 처리하지 않는다. 비밀키 연결 후 실제 OAuth·권한 차단·재방문을 확인하며, 실제 리뷰 공개는 선택된 글 없이 합성 글로 대신하지 않는다. 검증된 사실은 발생일의 canonical Daily에 기존 독립 항목을 보존해 연결하고, 기존 미확정 논문 리뷰 초안은 그대로 로컬에 둔다.
